- **재시도**: rpc 가 error 를 주거나 throw 하면 `logger.error({ pgError: safePgError(err), batch: n, firstSeq, lastSeq }, "[journal] dma_journal_apply 실패 — 같은 배치 재시도")` 후 `backoffDelayMs` 규칙(1→2→4→…→30초, `dma-client.ts` 정본 import · 값 복제 금지)으로 같은 배치를 다시 보낸다. 실패 중 `lastAppliedSeq` · 커서는 전진하지 않는다(커서는 RPC 트랜잭션 안에서만 전진 — 유실 0 의 근거). `consecutiveFailures >= dbErrorAfter` 면 `dbError = true` 로 바꾸고 `emit("health", health())`, 성공하면 되돌리고 다시 emit.
- **연속성**(push 시점 · 동기): `lastReceivedSeq` 가 null 이 아니면 seq ≤ 그 값은 중복으로 건너뛰고(debug 로그), 첫 비중복 레코드가 `lastReceivedSeq + 1` 이 아니면 그 앞까지만 적재하고 `"gap"` 을 돌린다(`logger.error({ expected, got }, "[journal] seq 갭 — 연결을 끊고 since_seq 로 다시 받는다")`). 적재한 마지막 seq 로 `lastReceivedSeq` 를 갱신한다. 큐 길이 + 새 건수가 `maxQueue` 를 넘으면 아무것도 적재하지 않고 `"overflow"`(warn).
- **epoch**: `readCursor()` 는 `dma_journal_cursor` 에서 `gateway` 로 1행을 읽어(서비스롤 select · maybeSingle) `epoch`·`lastReceivedSeq` 를 초기화하고 `JournalCursor` 를 돌린다(오류는 safePgError 로그 후 throw). `beginEpoch(epoch, { resync })` — `resync` 이거나 epoch 가 현재와 다르면 새 epoch 로 바꾸고 `lastReceivedSeq = null`(첫 레코드는 갭 판정 없이 수용), resync 면 `logger.error({ from, to }, "[journal] 저널 재동기화 — epoch 변경 또는 보관 범위 밖")`(Pitfall 3 — 조용한 전면 누락을 드러낸다). 큐의 옛 epoch 항목은 그 epoch 로 먼저 나간다.
- **관측 게터**: `epoch` · `lastReceivedSeq` · `lastAppliedSeq` · `queueDepth` · `health(): JournalWriterHealth { queueDepth; consecutiveFailures; dbError; lastAppliedSeq; lastAppliedAtMs }` — 이 타입을 types.ts 에 더한다.
- **종료**: `drain(timeoutMs): Promise<boolean>` 은 큐가 비고 진행 중 호출이 끝나면 true, 시간 초과면 false(남은 건수 warn — 커서가 전진하지 않았으므로 다음 부팅이 재생한다는 문구). `close()` 는 재시도 타이머를 지우고 이후 push 를 거부(warn)한다. 모든 타이머는 `unref`.
