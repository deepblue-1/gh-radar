오늘 주문 행 펼침 — today-orders-card 목업

Phase 25 ① 오늘 주문 카드 행 펼침. 행을 클릭하면 실제로 열리고 닫힙니다(기본 몇 개는 열어 둠). 데이터는 기획서 예시 하루 흐름(○○전자 선매수 12451 · 후매수 12453 취소 · 자동 매도 조각 7건)을 그대로 씀. 저널 통보 = 통보 배지(접수/체결/취소 확인), 전략 이벤트 = 상따 배지(주문 근거/대기/첫 체결/취소 사유). 시각은 ms.

결정 1 — 펼쳤을 때 무엇을 보이나 (3안)

1-A안 · 통보 + 전략 이벤트를 한 타임라인에 (gw_time_ms 순, 배지로 출처 구분)

접수 → 대기(체결예상) → 체결 조각(누적 running sum) → 첫 체결 오차 → 취소 확인 → 취소 사유(남은 거래량) 가 인과 순서 그대로 한 줄기. 수동 주문 행은 통보만 나옴. RPC 는 두 테이블 UNION 1회.

1-B안 · 전략 이벤트만 (기획서 7종만, 통보 조각은 행 요약으로 갈음)

접수·체결 조각·취소 확인 줄이 없다. 줄 수가 적고 「왜 냈나」 만 남음. 수동 주문 행·전략 이벤트 없는 행은 펼쳐도 빈 안내 한 줄. 체결 조각을 보려면 작업대 주문로그 탭이 아니라… 볼 곳이 없음(통보는 어디에도 평면으로 안 보임).

1-C안 · 두 구획 분리 (위 전략 이벤트 · 아래 통보)

출처별로 나눠 각각 시간순. 섞이지 않아 읽기 명확하나 「대기 → 체결」 인과는 눈으로 두 구획을 오가며 맞춰야 함. 펼침 높이가 가장 큼.

결정 2 — 묶인 행(자동 매도 조각 7건, 3초 창)을 펼치면 (2안)

현재 카드는 상따/VI 자동 주문을 3초 창으로 한 행에 묶는다(#12461~12467 (7건)). 아래는 1-A안(합친 타임라인) 기준.

2-A안 · 묶음 전체 이벤트를 한 타임라인에 (줄마다 주문번호 꼬리)

RPC 가 order_no 배열을 받아 7건 이벤트를 시간순 한 목록으로. 클릭 1회 = RPC 1회. 줄 수가 많아짐(7건 × 2~3줄).

2-B안 · 펼치면 묶음을 풀어 주문별 행 → 각 행을 다시 펼침 (2단)

1단: 묶인 행 클릭 → 7개 주문 행이 들여쓰기로 나열(각 행에 자기 수량·가격·상태). 2단: 개별 행 클릭 → 그 주문의 타임라인. 한 번에 보이는 양이 통제되지만 두 번 클릭.

결정 3 — 펼침 트리거 (2안)

3-A안 · 행 전체 클릭 (시각 앞 ▸ 표식이 회전) · 여러 행 동시 펼침

위 목업 전부가 이 방식. 행 어디를 눌러도 토글. 열린 행은 옅은 primary 배경.

3-B안 · 우측 끝 화살표 버튼만

주문번호 뒤에 ⌄ 버튼 열 추가(표 폭 +30px). 행 클릭은 무동작. 모바일에선 상태 칩 옆에 놓임.
