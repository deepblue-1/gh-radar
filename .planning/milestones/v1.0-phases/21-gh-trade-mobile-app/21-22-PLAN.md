<objective>
G-21-N3 (iOS · iPadOS): 앱 WebView 에서 **서버 호스트 밖 http(s) 최상위 이동과 새 창 요청**을 SFSafariViewController(앱 위 인앱 브라우저, 프레임워크 내장 — 새 의존성 없음)로 연다. 같은 호스트는 WebView 에 머물고(새 창 요청 포함), 비 http(s) 는 지금의 Capacitor 기본 경로 그대로다. 웹 코드와 npm 패키지는 건드리지 않는다(21-UAT.md G-21-N3 사용자 결정 2026-09-26 · CONTEXT D-28).

Purpose: 뉴스·종토방 원문을 읽고 닫으면 곧바로 앱의 같은 화면으로 돌아온다. Android(21-17)와 같은 판정 표를 써서 두 플랫폼의 경계가 갈리지 않게 한다.
Output: Swift 1(순수 판정) + 표 검사 스크립트 2 + 프록시 확장 + VC 배선 1줄 + pbxproj 등록 + `native:check-external-links:ios`.

**플래너 실측(2026-09-26 · Capacitor iOS 8.5.2 `WebViewDelegationHandler.swift`):**
- `decidePolicyFor`: 플러그인 `shouldOverrideLoad` → `allowNavigation` → 최상위(`targetFrame == nil` 또는 메인 프레임) 이면서 앱 URL 접두가 아니면 `UIApplication.shared.open` 후 cancel(= 지금의 외부 Safari 동작) → 그 외 allow. 설치된 플러그인 중 `shouldOverrideLoad` 구현은 없다(capgo 0건).
- `createWebViewWith`(WKUIDelegate): URL 이 있으면 무조건 `UIApplication.shared.open` 후 nil — 같은 호스트 `target=_blank` 도 Safari 로 나간다(Android 는 멀티 윈도우 미사용이라 같은 WebView 에서 열림 — 플랫폼 간 불일치).
- 웹 `target=_blank` 앵커는 먼저 `decidePolicyFor`(targetFrame nil)를 지나고, 허용되면 `createWebViewWith` 가 불린다. `window.open` 은 곧바로 `createWebViewWith` 로 올 수 있다 → 두 곳 모두 가로챈다.
- `NavigationDelegateProxy` 는 실패 콜백 두 개만 구현하고 나머지는 `responds(to:)` · `forwardingTarget(for:)` 로 원본에 넘긴다(T-21-37). `uiDelegate` 는 아직 Capacitor 핸들러가 직접 받는다.
- 시스템으로 꼭 넘겨야 하는 호스트는 없다(21-15 네이티브 Google 로그인 — `/login` 앱 분기는 웹 OAuth 전에 반환). `allowNavigation` 은 계속 비운다.

커밋 규율: 한글 메시지 · **Co-Authored-By 줄을 넣지 않는다** · 파일 지정 add · 커밋 직전 `git status -sb` · **push 금지**(21-24 체크포인트).
