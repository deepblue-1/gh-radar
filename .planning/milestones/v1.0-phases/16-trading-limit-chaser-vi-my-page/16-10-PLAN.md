`RelayProvider` 에 아래를 추가한다:

- `sendOrder(req: { kind:"new"|"cancel"; isin; exchange; side?; orgOrderNo?; qty; price; accountNo }): Promise<{ orderNo: string; resultCode: number; message: string; status: "accepted"|"rejected"|"filled"|"partially_filled"|"cancelled"|"timeout" }>`
  - `rid` 생성: `crypto.randomUUID()`.
  - 대기 맵 `Map<rid, {resolve, timer}>` 을 ref 로 둔다. `applyFrame` 의 `order.result` case 가 이 맵을 찾아 resolve 하고 **상태에는 쌓지 않는다**(1회성).
  - 클라이언트 타임아웃 = `ORDER_REQUEST_TIMEOUT_MS`(9초, relay 5초보다 김). 초과 시 `status:"timeout"` 으로 resolve 한다 — **reject 하지 않는다**(호출부가 catch 로 「실패」 렌더하는 경로를 만들지 않기 위해).
  - 소켓이 닫혀 있거나 `status !== "ready"` 면 즉시 `status:"rejected"` + `ORDER_ERROR_CODES` 중 적절한 코드로 resolve 하고 **사유를 로그**한다(조용한 무시 금지).
  - 연결이 끊기면 대기 중인 rid 를 전부 `timeout`(결과 모름)으로 정리한다 — 「보냈는지 모른다」가 정확한 상태다.
  - 중복 가드: 같은 rid 는 만들지 않으므로 호출부 더블클릭 방지는 기존 `submitting`/`blocked` 가드가 담당한다.
  - `market` 은 보내지 않는다(relay 가 ISIN 으로 해석 — 16-08).
  </action>
