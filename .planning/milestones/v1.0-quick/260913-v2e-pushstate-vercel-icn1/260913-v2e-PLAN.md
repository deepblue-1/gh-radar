## 요구 (이 퀵에서만 쓰는 ID)

- **V2E-02** webapp 서버리스 함수를 iad1 → icn1 로 옮긴다.

## 진단 (오케스트레이터 제공 + 플래너 코드 확인)

1. `stock-detail-tabs.tsx:74` 의 활성 탭은 `useSearchParams()` **하나**에서만 나온다. `:81` 이 라우터 내비게이션을
   부르므로 `?tab=` 이 바뀌려면 RSC 서버 왕복이 끝나야 하고, 그동안 탭 UI 가 멈춰 있다.
2. `webapp/src/app/stocks/[code]/page.tsx` 는 `searchParams` 를 읽지 않는다(grep 0건) — 서버 쪽에서 `tab` 에 따라
   달라지는 것이 없으므로 RSC 왕복을 건너뛰어도 잃는 것이 없다.
3. Next 설치본 **15.5.15** (`webapp/package.json` `^15.0.0`). 공식 문서(Linking and Navigating §Native History API):
   `window.history.pushState` 가 Next 라우터에 통합돼 `usePathname`·`useSearchParams` 와 동기화된다.
4. **★ 플래너가 찾은 함정 — 한 클릭이 기록 2개가 된다.** Radix `@radix-ui/react-tabs@1.1.13` 의 `TabsTrigger` 는
   `onMouseDown` **과** `onFocus`(자동 활성화, `!isSelected` 일 때) 둘 다에서 `onValueChange` 를 부른다. Chrome·안드로이드는
   버튼을 mousedown 에 포커스하므로 한 클릭에 두 번 불린다. Next 가 패치한 pushState 는 라우터 상태 갱신을
   `startTransition` 안에서 하므로 focus 시점의 `isSelected`·`active` 는 아직 낡아 있다 → 두 번째 호출도 통과한다.
   종전 라우터 내비게이션은 Next 의 HistoryUpdater 가 같은 URL 푸시를 합쳐 줘서 드러나지 않았다. **네이티브
   pushState 는 합쳐 주지 않으므로 가드가 없으면 뒤로가기를 두 번 눌러야 이전 탭으로 간다 — T3 위반.**
   반면 이미 활성인 탭을 다시 누르는 경우는 Radix `useControllableState@1.2.2` 가 `value2 !== prop` 일 때만
   onChange 를 불러 원래 걸러진다.
5. `webapp/vercel.json` 에 `regions` 가 없어 함수가 iad1 에서 돈다(2026-09-13 실측 `x-vercel-id: icn1::iad1::…`,
   한국에서 TTFB 0.34–1.16s). 백엔드 Cloud Run 은 asia-northeast3(Phase 02 D-27, Supabase 리전과 매칭해 서울 선택)
   → icn1 이 둘 다에 맞다. Vercel 문서: `regions` 는 프로젝트 설정의 Function Region 을 덮어쓰고, Hobby 도 단일 리전 선택 가능.
