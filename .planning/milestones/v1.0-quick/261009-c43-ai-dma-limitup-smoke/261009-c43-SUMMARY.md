# Quick 261009-c43: AI 애널리스트 DMA 매핑 게이트 + smoke INV-2 폴링 Summary

AI 애널리스트를 서버 `requireDmaMapped`(dma_visible_accounts RPC 1회)로 DMA 매핑 사용자 전용으로 실제 차단하고, 웹 `/chat` · 종목상세 FAB · 앱 「AI 분석」 은 접근 탐침(`GET /api/chat/access`) 결과로 깜빡임 없이 DmaGate 를 보이거나 버튼을 숨긴다. smoke-limitup-sync INV-2 는 10초 × 최대 9회 재조회로 Cloud Logging 수집 지연 오탐을 없앴다.

## ★ 배포 순서 (메인 세션 실행 — 이 실행자는 배포 · push 하지 않았다)

1. **server 먼저 배포** (Cloud Run `gh-radar-server` 새 revision).
2. **확인:**
   - 매핑 계정 토큰으로 `GET /api/chat/access` → `200 {"access":true}`
   - 미매핑 계정 토큰 → `403 {"error":{"code":"DMA_UNMAPPED",...}}`
   - 무토큰 → `401`
3. **그 다음 push** (push = Vercel webapp 프로덕션 배포).

웹이 먼저 나가면 `/api/chat/access` 가 404 라 탐침이 `"error"` 가 되어 `/chat` 이 모두에게 오류 상자(다시 시도)를 보이고, FAB · 앱 「AI 분석」 이 사라진다. 서버만 먼저 나간 상태는 안전하다 — 기존 웹은 탐침을 부르지 않고, 미매핑 사용자의 챗 호출만 403(기존 웹에서는 일반 오류 표시)이 된다.

앱 릴리스 없음(D-04 — `mobile/` · 탭 표 무변경. 앱 AI 탭은 `/chat` 을 열고 그 페이지가 DmaGate 를 보인다).

## Phase 29 D-21 전제

Phase 29 D-21(「AI 애널리스트는 DMA 연결 사용자 전용 · DMA_UNMAPPED 403 게이트 유지」)은 이 게이트가 이미 있다고 전제했지만, 실제로는 사이드바 숨김뿐이었다. 이 quick 이 그 게이트를 실제로 만들었다 — 서버 차단 원천은 상한가 보고서 RPC 게이트와 같은 `dma_visible_accounts(p_user_id)` 이고, 오류 생성자 `DmaUnmapped` 는 `server/src/errors.ts` 로 옮겨 두 표면이 공유한다(문구 글자 그대로).

## 재량 결정

- **relay 신호 미사용(D-02):** AI 애널리스트는 relay 표면이 아니다. relay 가 내려가 있어도 써야 하고, 표시 판정이 서버 차단과 같은 원천을 봐야 둘이 갈리지 않는다.
- **비로그인 FAB 로그인 다이얼로그 제거(D-03):** 앱 전체가 로그인 벽 뒤라 비로그인 사용자는 종목상세에 닿지 못한다(chat.spec 260912-ok2). 이제 FAB 은 판정 ok 가 아니면 아예 없다.
- **판정 기억 정책:** `ok` 는 탭 수명 동안 기억(앱 AI 탭 재방문 시 첫 렌더부터 본문) · `unmapped` 는 5분만(관리자가 DMA 를 연결하면 5분 안에 풀림) · 401/오류는 기억 안 함. 사용자 전환 시 AuthProvider 의 clearQueryCache 가 비운다. 같은 사용자 동시 탐침은 모듈 수준 Map 하나로 합친다(FAB + 히어로 버튼).
- **세션 중 연결 해제:** /chat 에서 스트림(ChatStreamError `DMA_UNMAPPED`) 이나 대화 열기(ApiClientError 403) 가 403 이면 `markUnmapped()` 로 DmaGate 전환.
