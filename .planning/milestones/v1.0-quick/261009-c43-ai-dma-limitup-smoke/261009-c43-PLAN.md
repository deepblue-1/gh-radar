(1) AI 애널리스트를 DMA 매핑 사용자(트레이딩 권한자) 전용으로 **실제로** 막는다. 지금은 사이드바 숨김뿐이라(app-sidebar.tsx 주석 ④ — 숨김은 권한이 아니다) 비권한 로그인 사용자도 네이티브 앱 AI 탭 · 종목상세 FAB · 앱 히어로 「AI 분석」 · `/chat` 직접 주소 · 서버 챗 API(Sonnet 5 비용)로 들어간다.
(2) `scripts/smoke-limitup-sync.sh` INV-2 가 Cloud Logging 수집 지연으로 가끔 FAIL 하는 것을 폴링으로 고친다.

이 quick 의 결정(이 계획에서 정한 ID — 태스크가 인용한다):
- **D-01 실제 차단 = server.** 새 미들웨어 `requireDmaMapped()` 를 챗 라우트 전부에 건다. 판정 원천은 상한가 보고서 RPC(`limitup_report_for_user` 안의 `EXISTS (SELECT 1 FROM dma_visible_accounts(p_user_id))`)와 **같은 함수** `dma_visible_accounts(uuid)` 다(service_role EXECUTE 전용 · 시그니처는 Phase 29 가시성 v2 전후 동일 — 마이그레이션 무변경). 상한가 보고서는 판정이 RPC SQL 안에 있어 추출할 TS 함수가 없다 — 공유하는 것은 오류 생성자 `DmaUnmapped` 하나(`server/src/errors.ts` 로 옮김)이고, 판정 로직은 새 미들웨어 한 곳에 둔다. Phase 29 D-21(「AI 애널리스트는 DMA 연결 사용자 전용 · DMA_UNMAPPED 403 게이트 유지」)이 이미 이 게이트를 전제하고 있다 — 이 quick 이 그 전제를 실제로 만든다.
- **D-02 웹 `/chat` = 표시 장치.** 페이지가 서버 접근 탐침(`GET /api/chat/access`)으로 판정하고 미매핑이면 `<DmaGate surface="AI 애널리스트">` 를 그린다. 상한가 보고서처럼 「판정 전엔 본문을 그리지 않고 서버 403 이면 게이트」 규율을 따른다. 단 relay 신호(`useDmaGateReason` 의 `unauthorized`)는 쓰지 않는다 — AI 애널리스트는 relay 표면이 아니라 relay 가 내려가 있어도 써야 하고, 표시 판정이 서버 차단과 같은 원천을 봐야 둘이 갈리지 않는다(재량).
- **D-03 진입 버튼은 판정 ok 일 때만 렌더.** 종목상세 FAB · 앱 히어로 「AI 분석」 은 같은 탐침 훅으로 판정 전 숨김. 비로그인 FAB 로그인 다이얼로그는 없앤다 — 앱 전체가 로그인 벽 뒤라(chat.spec.ts 260912-ok2 주석) 비로그인 사용자는 종목상세에 닿지 못하고, 이제 FAB 은 판정 ok 가 아니면 아예 없다(재량).
- **D-04 네이티브 앱 AI 탭은 그대로.** 탭 표 · `mobile/` 무변경. 앱 AI 탭은 `/chat` 을 열고, 그 페이지가 D-02 로 DmaGate 를 보인다.
- **D-05 smoke INV-2 폴링.** 기존 관례(smoke-home-sync.sh · smoke-theme-sync.sh 의 「N회 × sleep 재시도로 ingestion lag 흡수」 고정 횟수 루프)를 따르되 요청대로 10초 간격 · 최대 9회(≈90초).

건드리지 않는 것: Phase 29 소유 파일(`server/src/middleware/require-admin.ts` · `webapp/src/lib/supabase/access-gate.ts` · `webapp/src/lib/supabase/middleware.ts` · `webapp/src/hooks/use-app-role.ts` · `supabase/` 전부) · 사이드바 노출 조건(`useTradingVisible` 그대로 — 주석만 갱신) · ChatSheet 본체(여는 경로가 D-03 으로 닫힌다) · 배포.
