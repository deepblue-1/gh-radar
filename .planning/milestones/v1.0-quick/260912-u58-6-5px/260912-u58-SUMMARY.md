## 항목 6건 처리 결과

### ① 종목 검색 결과 — ↓/↑/Enter 탐색 · `6fe6d7e`

`StockSearchField` 를 ARIA combobox 로 올렸다. **포커스는 입력에 남고** 활성 항목만
`aria-activedescendant` 로 옮긴다 — 로밍 tabindex 로 실제 포커스를 항목에 옮기면 래퍼 `onBlur` 의
「밖으로 나가면 취소」 계약과 싸운다.

- ↓/↑ 는 `isPickable` 로 걸러 **고를 수 있는 행만** 지난다. 끝에서는 **멈춘다**(순환 없음).
- Enter 는 활성 항목을 고르고, **활성 항목이 없으면 아무 일도 하지 않는다**(첫 항목 자동 선택 금지).
  `preventDefault` 는 활성 유무와 무관하게 건다 — `type="search"` 의 폼 제출 누출 차단.
- 활성 항목을 **인덱스가 아니라 종목코드**로 들고 있다. 목록이 갱신되면 그 코드가 사라져
  파생값이 스스로 null 이 된다 — 「초기화를 잊는」 경로가 없다.
- 목록이 없을 때 `aria-controls`/`aria-activedescendant` 를 걸지 않는다(없는 id → axe critical).
- `role="option"` 은 `<li>` 가 아니라 기존 버튼이 갖는다(`nested-interactive` 회피).
  안내 문구 `<li>` 는 `role="presentation"`.
- 기존 4경로 전부 살아 있다: Esc 취소 · 컨테이너 밖 blur 취소 · `<ul>` mousedown 억제 · **마우스 클릭**.

유닛 8건 신규. 마우스 클릭 경로는 **새 케이스를 만들지 않았다** — 기존 `pickThenOpenSearch` 와
⑯ 선택 케이스들이 이미 `click()` 으로 `onPick` 을 지나고 있어 중복이 된다(계획 지시대로 확인만).

`role="combobox"` 가 e2e `getByRole('searchbox')` 3곳을 죽이므로 **같은 커밋에서** 함께 고쳤다.
단순 치환하지 않고 `getByRole('combobox', { name: '종목 검색' })` 로 좁힌 지역 헬퍼 `searchBoxOf()`
하나에 모았다 — 같은 카드의 거래소 `<select>` 도 combobox 라 이름이 없으면 strict mode 위반이다.
`a11y.spec.ts` 의 `/trading/limit-chaser/new` 케이스에 **결과 목록이 뜨고 ↓ 로 활성이 생긴 상태**의

### ⑥ 와이드 밴드 체결가 5px 잘림 · `462b250`

폭 예산이 거꾸로 서 있었다 — 시각·수량이 `flex-none` 이고 체결가만 `flex-1 truncate` 라

`formatTapeTimeShort` 가 컴팩트 테이프에서 쓰는 것과 같은 근거다.

부수효과가 **0** 인 것이 이 방법의 요점이다: 접두 span 에 `text-[10px]` 을 걸지 않아 케이스 ⑪ 의

### 2. [Rule 3 - 차단 해소] combobox 에 `jsx-a11y/role-has-required-aria-props` 한 줄 억제

- **발견 시점:** Task 1, lint 게이트에서 warning 3 → 4
- **원인:** 그 규칙은 **ARIA 1.1** 판이라 combobox 에 `aria-controls` 를 **항상** 요구한다.
  ARIA 1.2(와 axe)는 `aria-expanded="false"` 일 때 요구하지 않는다.
- **판단:** 규칙을 따르면 목록이 없을 때 **존재하지 않는 id** 를 가리켜
  `aria-valid-attr-value`(**critical**)로 바뀐다 — warning 1건을 끄려고 critical 1건을 만드는
  거래다. 해당 한 줄만 `eslint-disable-next-line` 하고 그 근거를 코드 주석에 남겼다.
  warning 은 기준선 **3** 으로 복귀.

### 3. [기록] ⑤ 커밋 메시지의 「유닛 820 passed」는 ⑥ 소스가 들어 있던 트리에서 잰 값이다
