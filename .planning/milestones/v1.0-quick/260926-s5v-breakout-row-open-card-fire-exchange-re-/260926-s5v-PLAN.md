## gh-radar 대응 (이 plan 의 결정)

| gh-trade | gh-radar |
|----------|----------|
| 상따창 새로 열기 + 발화 거래소 | 카드 새로 만들기 · 거래소 = 발화 거래소 |
| 라디오 비활성 → 요청 무시 | `exchangeChoicesOf(isin, "KRX", nxtTradable)` 에 요청 거래소가 없으면 요청 없음(null) — 판정 한 벌(종목상세·카드 헤더와 같은 함수) |
| 같은 종목 창 재사용 + `SelectExchange` | 그 ISIN 카드 재사용. 발화 거래소 키 카드가 있으면 그것을 펼치고, 없으면 포커스 카드를 `changeExchange` 로 전환 |
| `RemoveRow` + `ReleaseRow` | 지운 행은 보이지 않고 **구독 후보에서도 빠진다** |
| 새 76 → `AddNewRow(highlight)` | 새 구간 원소 → 옛 기록(meta · firstTime) 폐기 후 새 등재 |
| 재돌파 소리 없음(하루 1회) | 「오늘 울린 종목」(ISIN) 그대로 → 무음 |
| `RowAdded` → 작업표시줄 깜빡임 | 「돌파 목록에 추가됐어요」 토스트 — 스트립의 새 비무음 행 신호로 낸다 |
| 78 없던 종목 → 무음·무강조 새 행 | 새 구간 78 원소 → 무음·무강조 새 행 · 토스트 없음 |

**왜 「새 구간」을 (돌파시각, 발화 거래소)로 판정하나.** gh-radar 의 relay 캐시는 76 을 upsert 만 하고 이탈 종목을 빼지 않는다. 그래서 브라우저 재접속 78 이 **이미 이탈한 종목의 옛 원소**를 새 객체로 다시 보낸다. 지금처럼 「객체가 바뀌면 되살림」 규칙에 새 행 의미를 얹으면, 재접속마다 지운 행 전부가 3초 유예 동안 다시 보인다. gh-trade 서버 78 은 above 종목만 담으므로 이런 일이 없다. 서버 상태의 구간 식별자는 `crossTime`·`crossExchange` 다(`rate-cross-alert.md:64-66`). 76 은 엣지마다 새 구간이라 시각이 반드시 바뀐다. 따라서 구간 동일성 = (exchangeTime, exchange) 로 판정하면 gh-trade 결과와 같아진다.
