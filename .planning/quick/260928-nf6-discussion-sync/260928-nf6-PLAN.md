**현황 (근거):**

- `src/index.ts:85-95` 의 onRequest 는 요청마다 incrementUsage(원자적 RPC)를 부르고, used > cap 이면 stopAll 하고 false 를 돌려준다. 이미 하드캡이다.

**방식 선택: (a) 하한 판정 + 하드캡. (b) 는 쓰지 않는다. 근거:**
- (b) 로 모드를 사전에 재현하려면 collectDiscussions 의 getLastScrapedAt(discussions 를 scraped_at desc 로 정렬해 limit 1) 을 종목마다 먼저 불러야 한다. 104번 DB 왕복이 늘거나, 새 집계 RPC 와 마이그레이션이 필요하다. isStale 판정 로직도 두 벌이 된다. 요청이 금지한 "추가 DB 왕복·중복 로직" 에 정확히 해당한다.
