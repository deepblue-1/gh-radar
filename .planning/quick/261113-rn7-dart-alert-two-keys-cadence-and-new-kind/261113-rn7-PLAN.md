**B. 키별 레인(Task 1) — `collector.ts`**

- `KeyLane`(키마다 하나 · 키 1 · 2 고정): `key` · `watches`(이 실행 `d.watches` 중 그 키 것) · `usedKnown` · `sinceFlush` · `warned80` · `unknownStreak` · `paused`(null 또는 `{ reason, code, err, retryAt, fresh }`). 이 실행이 「쓰는 키」 = 감시 대상이 하나 이상인 키(auto · seed), probe 모드는 키 2 하나.
- 멈춤 이유 `PauseReason` = 기존 `HaltReason`(quota · dart_key · dart_bug · unknown_streak) + `budget_exhausted` · `probe_failed`. `retryAt` = 멈춘 시각 + `KEY_PROBE_RETRY_MS`(300,000 — 옛 「다음 5분 깨움이 탐침 1건」 과 같은 빈도) · 예산 소진은 `Infinity`(그날 다시 부르지 않음).
- 치명 신호(`countedList` → `noteListError`)는 그 키 레인을 곧바로 `paused`(fresh) 로 만든다 — 같은 바퀴의 그 키 남은 감시 대상은 `isDue` 가 false 라 부르지 않는다(호출 0 · 결과 항목 없음). `isDue` = 「그 키가 멈추지 않았고 그리고 `takeSlot`」 — 멈춘 키는 칸을 소비하지 않는다.
- 바퀴 끝(`stopOnHalt` 자리)의 `settleHalts()`: fresh 레인마다 fresh 를 끄고 quota · unknown_streak 면 그 키로 한도 의심 표시 기록. 쓰는 키가 전부 멈췄으면 지금처럼 error `fatal DART status — stopping this run` 뒤 `StopRun(1, 마지막 멈춤 이유, code)` — 키 1 만 쓰는 실행(시험 기본)은 동작 · 로그 · 종료 이유가 지금과 똑같다. 아니면 fresh 레인마다 error `dart key paused — other key keeps running`(`{ key, reason, err, retryAt }`) 뒤, 임대가 있고 창 안이고 열린 장애가 없으면 `openOutage("<그 키 감시 대상 이름들 · 로 이음> — <FATAL_OUTAGE_REASON[이유](code)>", now)`.
- 바퀴 시작의 `retryPausedLanes(startedAt)`: 멈춘 레인 중 `retryAt <= now` 인 것마다 `dart.probe(오늘, key)` 1건(그 키 카운터에 셈) → 성공이면 `paused = null` · `unknownStreak = 0` · info `dart key probe ok — resuming` 뒤 같은 바퀴에서 그 키 감시 대상을 부른다 / 실패면 `retryAt = now + KEY_PROBE_RETRY_MS` · warn `dart key probe failed — retrying in 5 min`(메일 없음 — 장애 글 · error 는 멈출 때 이미 냈다) · 한도 의심 표시는 더하지 않는다(옛 탐침 실패와 같음).
- 예산(`budgetGate` · `maintain(gate=true)`): 레인마다 `usedKnown + sinceFlush` 가 예산 이상이면 그 레인을 `budget_exhausted`(fresh · retryAt Infinity)로 멈춘다. 쓰는 키가 전부 멈췄으면 지금처럼 error `daily budget exhausted — stopping this run` + `StopRun(1, "budget_exhausted")`, 아니면 error `dart key paused — other key keeps running`(reason budget_exhausted · used · budget) — 장애 글은 그 바퀴 끝 `settleHalts` 가 연다. `DART_ALERT_DAILY_BUDGET` 값 하나를 키마다 따로 적용.
- 시작(`main`): `budgetAtStart` 는 쓰는 키마다 읽고, 다 찬 키는 fresh 아님으로 멈춘다(앞 실행이 이미 글을 냈다) · warn `daily budget already reached — not calling OpenDART` 에 key · 쓰는 키가 전부 찼으면 지금처럼 종료 0 `budget_at_start`. 한도 의심 탐침은 쓰는 키마다(키 1 → 키 2 순) 그 키 표시가 1 이상이고 예산으로 멈추지 않았으면 `probe(오늘, key)` 1건 → 성공 info `quota probe ok — resuming collection`(key) / 실패면 그 레인을 `probe_failed`(fresh · 5분 뒤 재탐침)로 멈춤. 쓰는 키가 전부 멈췄으면 지금처럼 error `quota probe failed — stopping without retries (next run probes once again)` + `StopRun(1, "probe_failed", code)`. 남은 fresh 멈춤의 장애 글 · 로그는 `startupCheck` 다음에 부르는 `settleHalts()` 가 낸다.
- seed: seed 바퀴 전에 멈춘 레인이 있으면(시작 탐침 실패 · 예산) error `seed failed — a DART key is paused, nothing inserted` 뒤 `StopRun(1, "seed_failed")`. seed 바퀴 실패 길의 한도 의심 표시 기록은 fresh 레인 기준(키별).
- 장애 닫기(`judgeOutage`): 이 바퀴 실패 0 이고 `failing` 이 비었고 **멈춘 레인이 없을 때만** `closeOutage`. 열기 쪽 `if (this.outage || this.halt)` 와 `judgeInsertFailure` 의 `this.halt` 는 「fresh 멈춤이 있는가」 로 바꾼다(치명 바퀴는 `settleHalts` 가 사유를 만든다).
- 사용량: `addCalls(key, n)` → `db.usage.add(n, key)` · 레인 `sinceFlush` · 80% 경고는 레인마다 1번 warn `daily budget 80% reached`(key 포함). `flushUsage` 는 쓰는 키마다 `db.usage.flush(date, key)`. stop 로그의 `usedToday` 는 `{ k1, k2 }` 객체로.
- probe 모드: 키 2 예산만 보고(`budget_at_start` 판단도 키 2) `dart.probe(오늘, 2)` 1건 · 카운터 키 2 · quota 실패면 키 2 한도 의심 표시.
- 장애 글은 DB 장애 칸이 한 줄이라 지금처럼 한 쌍이다: 먼저 막힌 키의 사유로 열고, 이미 열린 동안 다른 키까지 막히면 단체방 글은 더 없고 error 로그(→ 운영자 메일)만 남는다. 두 키 모두 회복해야 「다시 동작」. 키마다 따로 한 쌍을 내려면 DB 장애 칸을 늘리는 마이그레이션이 필요해 이번엔 하지 않는다(SUMMARY 의 사용자 확인 대기 항목).
