Task 1 의 0차 캘린더 게이트 **직전**에 probe 를 배치한다. 이유: 휴장일에도 probe 결과를 로그에 남겨야
A1(“휴장일엔 오늘 dt 봉이 생기지 않는다”)을 프로덕션에서 실측할 수 있다(RESEARCH V2. 오늘을 놓치면 다음 기회는 9/24).
즉 최종 순서는:

```
1. dateIso 계산 + cycle start 로그
2. isKrxCalendarStale warn
3. token 발급                                    ← 게이트보다 앞으로 이동 (probe 에 필요)
4. kiwoom client 생성                            ← 게이트보다 앞으로 이동
5. dtGuardEnabled 면 probe (probeCodes 각각, 실패는 개별 흡수)
     → log.info({ probes: [{code, latestDt}], todayBasDd, isHoliday }, "ka10081 dt probe")
6. isKrxHoliday(dateIso) → warn + return (0차) — probe 결과는 이미 로깅됨(관측 전용)
7. probe 성공 ≥1 && 모든 성공 probe 의 latestDt !== todayBasDd → warn + return (1차)
8. 기존 흐름 (fetchKa10027 …)
```
- `todayBasDd` = `dateIso.replace(/-/g, "")`.
- probe 는 `Promise.allSettled` 또는 순차 try/catch — **개별 실패가 cycle 을 죽이면 안 된다**.
  전부 실패면 `log.warn({ errors }, "ka10081 probe 전부 실패 — dt 가드 fail-open, 0차/2차/3차 가드로 진행")` 후 통과.
- 판정 규칙(보수적): `okProbes.length > 0 && okProbes.every(p => p.latestDt !== todayBasDd)` 일 때만 skip.
  하나라도 오늘 dt 가 있으면 거래일로 간주해 통과 — 역방향 오탐(A2)이 정방향 미탐보다 훨씬 치명적이기 때문.
- skip 로그: `log.warn({ probes, todayBasDd }, "ka10081 최신 dt !== 오늘 — 직전 거래일 재방출 판정, cycle skip (1차 dt 가드)")`.
- token 발급/ client 생성을 게이트 위로 올려도 휴장일 비용은 토큰 1 + REST 2회/분 수준(24 req/s 버킷 대비 무시 가능).
- **`withRetry` 로 probe 를 감싸지 말 것** — 재시도는 휴장일 skip 을 지연시킬 뿐이고, 실패는 fail-open 이라 무의미.
