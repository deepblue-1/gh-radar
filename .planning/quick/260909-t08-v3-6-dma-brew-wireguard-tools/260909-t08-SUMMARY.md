# quick-260909-t08: DMA 터널 mac 클라이언트를 brew wireguard-tools 로 교체 (v3.5 → v3.6) 요약

macOS 메뉴바 앱의 DMA 터널 제어를 **App Store WireGuard 앱 + 시스템 프로필 제어**에서
**Homebrew `wireguard-tools`(wg-quick + wireguard-go) 직접 제어**로 바꿨다. 사용자는 GUI 앱을
설치하거나 프로필을 import 하지 않고, `brew install wireguard-tools` 한 번과 설치 스크립트
재실행만으로 메뉴바 토글을 얻는다. 직전 quick 의 미검증 항목 ⑧(공백 포함 프로필 이름 `KB DMA`
가 앱에 수용되는지)은 터널 이름이 conf 파일명(`KB-DMA`)에서만 파생되므로 **문제 자체가 소멸**했다.

## 사용자 설치 절차 (순서대로)

```bash
# ① 도구 설치 — wireguard-go 와 brew bash 를 함께 끌고 온다 (스크립트는 이걸 대신 해 주지 않는다)
brew install wireguard-tools

# ② 관리자에게 두 값을 받는다
#    - 서버 공개키: 관리자가 VM 에서  sudo wg show wg0 public-key
#    - 배정 주소:   10.20.0.<N>   (N 은 2~254)

# ③ 설치 스크립트 실행 — 진행 중 위 두 값을 입력한다 (엔터 = 기존 값 유지)
bash scripts/install-vpn-menubar.sh
#    개인키는 $(brew --prefix)/etc/wireguard/KB-DMA.conf (root:wheel 0600) 안에만 들어간다.
#    화면에는 공개키 하나만 뜬다.

# ④ 화면의 공개키를 관리자에게 전달 → 관리자가 VM 에서
#    sudo /usr/local/sbin/wg-peer-add <이름> <공개키> 10.20.0.<N>

# ⑤ 등록되면 재실행 없이 메뉴바에서 터널 토글 → 도달성만 확인
nc -z 10.41.1.120 9100 && echo reachable
```

②를 아직 못 받았다면 ③은 WARN 을 내고 conf 를 만들지 않는다(터널 메뉴만 비활성, KB VPN 직결·교보는 정상).
값을 받은 뒤 ③을 다시 실행하면 채워지고, **재실행해도 개인키는 재생성되지 않아** 등록된 피어가 살아 있다.

문제 시 로그: `/var/log/kbdma.log` (wg-quick 출력) · `~/Library/Logs/dma-tunnel.log` (앱 판정 기록).

## 계획 대비 편차

### D1. base64 44자 게이트를 `VPN_PIN` 줄 제외로 한정 — **게이트 정의 수정**
- **발견 시점:** Task 1 착수 전 기준선 측정
- **문제:** plan 은 `grep -cE '[A-Za-z0-9+/]{43}=' = 0` 을 요구하는데, **변경 전 원본에서 이미 1건**이 나왔다.
  매칭 대상은 61행의 기존 `VPN_PIN`(TLS **인증서 핀**)이다 — WireGuard 키가 아니고, plan 이 "한 글자도
  건드리지 않는다"고 못 박은 값이다.
- **처리:** 게이트를 `grep -v '^VPN_PIN=' | grep -cE ...` 로 한정해 실행했고 **0건**이다.
  즉 이번 변경이 새로 들여온 base64 44자 문자열은 없다. 원본 파일을 수정하지 않았다.

### D2. `visudo -cf` 는 SKIP 이 아니라 **실행됐다**
- plan 은 `sudo -n` 불가 시 SKIP 을 허용했다. `sudo -n` 은 실제로 불가했지만,
  `/usr/sbin/visudo -cf <파일>` 은 **비루트로도 동작**해 `parsed OK` 를 얻었다. SKIP 대신 실측으로 기록한다.

### D3. [Rule 1 - Bug] BSD `awk` 가 기존값 추출 정규식을 파싱하지 못함 → `sed` 로 교체
- **발견:** 스텁 실행 검증(검증 #14) 중 `awk: syntax error`.
- **원인:** `sub(/^[^=]*= *//, "")` 의 `*//` 를 macOS `awk` 가 **정규식 두 개**로 읽는다.
- **수정:** `sudo sed -n '/^\[Peer\]/,$ s/^ *PublicKey *= *//p'` 와
  `sudo sed -n 's|^ *Address *= *||p' | cut -d/ -f1 | cut -d. -f4` 로 교체. 재검증 PASS.
- **의미:** 정적 문법검사만 했으면 놓쳤을 결함이다. 재실행 시 기본값이 안 잡히고 사용자가 매번
  두 값을 다시 입력해야 했을 것이다.

### D4. [Rule 1 - Bug] 주소 끝자리의 앞자리 0 정규화 추가
- **발견:** 검증 #16 에서 `07` 이 통과.
- **문제:** `Address = 10.20.0.07/32` 가 그대로 기록된다.
- **수정:** 검증 통과 직후 `ADDR_N="$((10#$ADDR_N))"` 로 10진 정규화(주석 포함). 재검증 PASS.

### D5. 키 생성을 `"$WG_BIN" genkey` 가 아니라 **PATH 고정 후 `wg genkey`** 로
- root 블록에서 `WG_DIR` 을 받아 `export PATH="$WG_DIR:…"` 한 뒤 `wg genkey` / `wg pubkey` 를 부른다.
- **이유 (둘 다):** ⓐ 헬퍼 2종이 쓰는 PATH 고정 패턴과 한 가지 방식으로 통일된다.
  ⓑ plan 의 `wg genkey` 정확히 1회 게이트를 문자 그대로 만족한다.
- 부산물로 쓰이지 않게 된 `WG_BIN`·`WG_GO` 변수를 탐지 블록에서 제거했다(탐지 자체는 3종 모두 그대로).

### D6. [Rule 2] conf 작성 실패가 `set -e` 로 즉사하지 않게
- `WG_PUBKEY="$( … )" || true` 를 붙이고 빈 값 판정으로 직접 처리한다.
  그렇지 않으면 스크립트가 아무 설명 없이 죽어 사용자가 원인을 못 본다.
