KB VPN 접속 파라미터(호스트·계정·authgroup·인증서 핀)와 교보 코드는 **한 글자도 건드리지 않는다.**
아래 변경분은 전부 DMA 터널 경로에 한정한다. 값을 SUMMARY·대화·로그에 옮겨 적지 않는다.

**(a) 변수 블록 (64~73행) 교체 — D-02**
`TUNNEL_NAME` · `WG_APP` 를 제거하고 다음을 정의한다:
`BREW_PREFIX` (= `brew --prefix` 성공 시 그 값, 실패 시 `/opt/homebrew` 존재 여부로 `/opt/homebrew` 또는 `/usr/local`),
`WG_CONF_DIR="$BREW_PREFIX/etc/wireguard"`, `TUNNEL_CONF="$WG_CONF_DIR/KB-DMA.conf"`,
`WG_ENDPOINT="dma.jx1.io:51820"`, `KBDMA_CONNECT_BIN="/usr/local/sbin/kbdma-connect"`,
`KBDMA_DISCONNECT_BIN="/usr/local/sbin/kbdma-disconnect"`, `KBDMA_LOG="/var/log/kbdma.log"`.
`WG_PREFIX`·`GW_ADDR`·`GW_PORT`·`HEALTH_URL`·`TUNNEL_LOG`·`SSH_*` 는 그대로 둔다.
터널 이름은 이제 conf **파일명**에서만 파생되므로(`KB-DMA`) 공백 없는 이름 한 곳(`TUNNEL_CONF`)만 정본이다.

**(b) §1 도구 확인 — WireGuard 앱 검사(149~161행)를 wireguard-tools 탐지로 대체 — D-01**
openconnect 탐지(130~140행)와 **같은 패턴**으로 `wg` · `wg-quick` · `wireguard-go` 를 각각
`command -v` → `/opt/homebrew/bin/<name>` → `/usr/local/bin/<name>` 순으로 찾는다.
셋 중 하나라도 없으면 `c_err "wireguard-tools 를 찾을 수 없습니다.  brew install wireguard-tools"` 후 `exit 1`.
**자동 설치 금지** — 스크립트가 brew 를 호출하지 않는다.
찾은 `wg-quick` 의 디렉터리를 `WG_BIN_DIR` 로 잡고(헬퍼 PATH 에 쓴다) `c_ok "wireguard-tools — $WG_QUICK"` 를 출력한다.

**(c) §3 뒤에 kbdma 헬퍼 2종 추가 — D-03**
기존 `sudo tee "$CONNECT_BIN"` heredoc 패턴을 그대로 복제해 두 파일을 만든다. 둘 다 `#!/bin/sh`, 인자 없음:
- `kbdma-connect`: 첫 줄에서 `export PATH="$WG_BIN_DIR:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"` 로 PATH 를 고정하고
  (`sudo` 가 `secure_path` 로 PATH 를 초기화해 `wg-quick` 이 `wireguard-go`·brew `bash` 를 못 찾는 함정 — 이유를 주석으로 남긴다),
  날짜 헤더 한 줄을 `$KBDMA_LOG` 에 append 한 뒤 `exec wg-quick up "<TUNNEL_CONF 절대경로>" >> "$KBDMA_LOG" 2>&1`.
- `kbdma-disconnect`: 같은 PATH 고정 후 `wg-quick down "<TUNNEL_CONF>" >> "$KBDMA_LOG" 2>&1` 을 실행하고
  **결과와 무관하게 `exit 0`** (이미 내려간 경우를 실패로 만들지 않는다).
두 파일 모두 `chown root:wheel` + `chmod 755`. `$KBDMA_LOG` 는 `touch` + `chmod 644`.
heredoc 안에서 확장되면 안 되는 `$` 는 기존 블록처럼 `\$` 로 이스케이프한다.

**(d) §3-b KB-DMA.conf 생성 — D-02 (§3 helper 설치 뒤, §4 sudoers 앞. sudo 프롬프트를 §3 것과 붙여 쓴다)**
1. `sudo mkdir -p "$WG_CONF_DIR"` → `chown root:wheel` → **`chmod 755`**.
   ⚠ D-02 는 디렉터리 0700 을 적었으나 D-04 preflight 는 앱(사용자 권한)이 conf 를 `test -e` 하도록 요구한다.
   0700 root 디렉터리는 사용자 프로세스의 traverse 자체를 막아 `test -e` 가 **항상 false** 가 되고 터널 메뉴가 영구 비활성된다.
   두 요구를 모두 살리는 유일한 조합이 **디렉터리 0755 root:wheel + 파일 0600 root:wheel** 이다.
   개인키 비공개는 파일 권한이 지키고, 디렉터리에서 드러나는 것은 이미 공개 문서에 있는 파일명뿐이다. 이 근거를 주석으로 남긴다.
2. 기존 conf 가 있으면 `sudo` 로만 읽어 `PublicKey` 와 `Address` 의 `<N>` 을 **기본값**으로 뽑는다 (값을 화면에 그대로 뿌리지 않는다).
3. `read -r` 로 서버 공개키와 주소 `<N>` 을 입력받는다(엔터 = 기존 기본값 유지).
   서버 공개키는 `^[A-Za-z0-9+/]{43}=$` (base64 44자), `<N>` 은 2~254 정수로 검증하고 불합격이면 재입력을 요구한다.
4. 값이 **비었고 기존 conf 도 없으면** conf 를 만들지 않는다. `PLACEHOLDER` 를 쓰지 않는다.
   `c_warn` 로 "서버 공개키·주소를 받은 뒤 이 스크립트를 다시 실행하세요 — 그 전까지 터널 메뉴는 비활성입니다" 를 알리고 설치는 계속한다.
5. conf 작성은 **단일 root 셸 안에서** 수행한다: `umask 077` → 기존 conf 가 있으면 그 안의 `PrivateKey` 를 재사용, 없으면 `wg genkey` 로 1회 생성 →
   `[Interface] PrivateKey/Address = 10.20.0.<N>/32` + `[Peer] PublicKey/Endpoint = $WG_ENDPOINT/AllowedIPs = $GW_ADDR/32/PersistentKeepalive = 25` 를 `$TUNNEL_CONF` 에 쓴다 → `chown root:wheel` + `chmod 600` →
   **`wg pubkey` 로 만든 공개키만** stdout 으로 돌려준다.
   D-02 가 예시한 `wg genkey | tee >(wg pubkey)` 는 개인키를 stdout 으로 흘리므로 **쓰지 않는다** — 개인키는 셸 변수와 0600 파일 밖으로 나가지 않는다(D-02 의 "화면·로그·클립보드 금지" 가 상위 요구).
   재실행 시 개인키를 재생성하지 않는 것이 등록된 피어를 살리는 조건이다.
6. 돌려받은 공개키를 출력하고 "이 값을 관리자에게 전달 → VM 에서 `sudo /usr/local/sbin/wg-peer-add <이름> <공개키> 10.20.0.<N>`" 를 안내한다.
