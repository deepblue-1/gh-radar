# relay 업타임 경보 싱가포르 AND 조건 + wg-probe hs_stale 기준 보정

## 배경

1. **업타임 경보 오탐.** 2026-09-17 03:39 KST 부터 미국·유럽·브라질 검사 지점만 10초 시간초과로
   실패하는 새 패턴이 나타났다. 싱가포르는 한 번도 실패하지 않았고, Caddy 가 받은 `/healthz` 는
   전부 약 2ms 에 200 이었다. 요청이 VM 까지 오지 않은 해외 경로 문제다. 현행 조건(6지점 평균
   5분 성공률 < 0.9)은 해외 5곳만 막혀도 울린다.
2. **wg-probe `hs_stale` 오탐.** 재부팅 뒤 휴면 피어 `10.20.0.2` 에서 1·49·5·8초짜리 에피소드가 떴다.
   - 경과가 180초를 넘는 순간 「최근 60초 내 이동」 조건이 **만료 전의 이동**으로 충족된다
     (hs_age=180 에서 시작해 60초 안에 닫힌 3건).
   - 20분 휴면 뒤 깨어날 때 첫 틱에 이동이 먼저 보이고 다음 틱에 핸드셰이크가 갱신된다
     (hs_age=1213, 1초 1건).

## 사용자 결정

- 경보 조건: 「평균 성공률 < 0.9 **AND** 싱가포르 지점도 실패」로 변경 (2026-09-17 승인).
- `hs_stale` 기준 보정 (2026-09-17 승인).

## 작업

### T1 — 경보 조건 (ops/alert-relay-down.yaml)
- 조건 2개 + `combiner: AND`. 조건 2 는 필터에 `metric.label.checker_location = "apac-singapore"` 를
  더한 같은 정렬(ALIGN_FRACTION_TRUE 300s, < 0.9, 지속 300s).
- 문서(runbook) §임계값과 오탐에 근거·대가(싱가포르 검사 지점 자체 장애 시 가려짐)를 추가.
- **검증:** 2026-09-06~09-17 분 단위 지점별 성공률로 백테스트. 기대: 실장애 5건 전부 유지,
  09-17 해외 경로 오탐 5건 전부 제거.
- **반영:** `deploy-relay.sh` 전체 재배포가 아니라 그 스크립트의 정책 갱신 단계만 같은 방식
  (`gcloud alpha monitoring policies update --policy-from-file`)으로 실행. 클라우드 측 변경이라 VM 무관.
  반영 후 `policies describe` 로 조건 2개·AND 확인.

### T2 — hs_stale 기준 (infra/relay/wg-probe.py)
- 새 정의: **키 만료(경과 >180초) 이후에 관측된 첫 바이트 이동**을 앵커로 삼아,
  그로부터 **≥3초** 핸드셰이크가 갱신되지 않고 ∧ 최근 60초 내 이동이 계속 있으면 발화.
  - 만료 뒤 이동이 있어야 하므로 만료 전 이동의 잔상(49초형)이 사라진다.
  - 3초 유예로 정상 깨어남(0~2초, 1Hz 양자화)이 사라진다. WireGuard 는 핸드셰이크 패킷 1개를
    잃으면 REKEY_TIMEOUT(5초) 뒤 재시도하므로 실제 손실은 여전히 잡는다.
  - `t0` = 앵커 → `close dur` 은 「데이터가 새 키를 기다린 실제 시간」.
  - 핸드셰이크가 갱신되면(경과 ≤180초) 앵커 해제.
- 신규 설정 `WG_PROBE_HS_GRACE_SEC`(기본 3), `start` 줄 `hs_grace_sec=` 추가.
- 헤더 §임계값 표의 hs_stale 행을 새 정의·실측 오탐 근거로 갱신 (정본은 여기 하나).
- self-check D3 유지 + **D6 신설**: ① 만료 전 이동 잔상 → 0건 ② 휴면 깨어남 1초 갱신 → 0건
  ③ 만료 뒤 이동이 10초 동안 핸드셰이크 없이 지속 → open 1 · close 1 · dur≈10.
- **검증:** 로컬 + VM(Python 3.11) `--self-check` 통과, D1 포함.
- **반영:** 장중이므로 startup.sh 재적용 없이 VM 에 파일만 설치 후 `systemctl restart wg-probe`
  (읽기 전용 측정기라 데이터패스 무관). 메타데이터는 `setup-relay-iam.sh` 의 add-metadata 로
  갱신해 재부팅 시에도 새 버전이 배치되게 한다 (메타데이터 갱신 자체는 VM 에서 아무것도 실행하지 않음).
  반영 후 `start` 줄의 `hs_grace_sec=3.0` 과 VM 파일 sha = 저장소 sha 확인.
