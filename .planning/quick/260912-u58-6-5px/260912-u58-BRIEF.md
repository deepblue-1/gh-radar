## ① 종목 검색 결과 — 화살표 키 탐색

`webapp/src/components/trading/limit-chaser-client.tsx` 의 `StockSearchField`(1050~).
지금은 `<input type="search">` + `<ul aria-label="종목 검색 결과">` + `<li><button data-slot="lc-search-option">` 이고, 키보드로는 Tab 으로만 항목에 닿는다.
**↓/↑ 로 목록 선택이 움직이고 Enter 로 고르게 한다.**

- **포커스는 입력에 남긴다.** 이 컴포넌트는 래퍼 `onBlur` 로 「밖으로 나가면 취소」를 구현하고 있어서, 실제 DOM 포커스를 항목으로 옮기는 로밍 tabindex 방식을 쓰면 그 계약과 싸운다. `aria-activedescendant` 패턴으로 간다: 입력에 `role="combobox"` · `aria-expanded` · `aria-controls` · `aria-activedescendant`, `<ul role="listbox">`, `<li role="option" aria-selected>`(각 항목에 안정적인 `id`).
- ↓/↑ 는 **고를 수 있는 항목만** 지나간다 — `isPickable(row)` 가 false 인 행(`isin === null` 또는 주문 불가 시장)은 건너뛴다. 그 행을 활성으로 만들면 Enter 가 아무 일도 하지 않아 「먹통」으로 읽힌다.
- Enter 는 활성 항목을 고른다(`onPick`). **활성 항목이 없으면 아무것도 하지 않는다** — 첫 항목을 자동으로 고르지 마라. `type="search"` 안에서 Enter 가 폼 제출로 새는 경로가 있으니 `preventDefault`.
- 목록이 갱신되면(query 변경 → 새 결과) 활성 인덱스를 **초기화**한다. 남겨 두면 다른 종목을 가리킨 채로 Enter 를 받는다.
- 활성 항목은 시각적으로도 구분된다(호버와 같은 배경이면 충분 — **새 색 토큰 만들지 마라**). `scrollIntoView({block:'nearest'})` 로 `max-h-60` 목록 안에서 따라간다.
- ★ **기존 Esc/blur 계약을 깨지 마라.** 래퍼의 `onKeyDown` Esc(전파만 중단, 기본동작 유지)와 `onBlur`(컨테이너 밖일 때만 취소), `<ul>` 의 `onMouseDown preventDefault` 는 그대로다. ↓/↑/Enter 만 새로 처리한다. **마우스 클릭 경로도 그대로 살아 있어야 한다.**
- 단위 테스트 추가: ↓ 로 활성 이동 · 비활성 행 건너뜀 · Enter 로 `onPick` · 목록 갱신 시 활성 초기화 · Esc 는 여전히 `onCancel`.

## ③ 종목명 트리거 외형

`limit-chaser-client.tsx:~552` `<button data-slot="lc-stock-trigger" … className="… border border-[var(--border-subtle)] …">`.
사용자: 「콤보박스 테두리는 필요없고 종목명 옆에 세모 아이콘만 잘 보여줘. 종목명 클릭해서 종목검색 되게 해주고.」

- **테두리(`border border-[var(--border-subtle)]`)를 제거**한다. 260912-mvo 가 「눌리는 컨트롤로 보이게」 하려고 넣은 것인데, 사용자가 그 대신 아이콘 쪽을 택했다. 그 판단을 뒤집는 것이므로 주석의 ⓑ 항목을 **지우지 말고 갱신**해라(무엇을 왜 되돌렸는지).
- `ChevronDown` 을 **더 잘 보이게** 한다: 현재 `size-3.5 text-[var(--muted-fg)]`. 색을 `--fg` 로 올리고 크기를 한 단 키운다(`size-4` / 데스크톱 `size-4.5` 수준). **정확한 값은 브라우저에서 보고 정해라** — 종목명(16px/20px) 옆에서 장식이 아니라 컨트롤로 읽히는 것이 기준이다. **새 색 토큰 만들지 마라.**
- `hover:bg-[var(--muted)]` 는 **남긴다** — 테두리를 뺀 뒤 「눌린다」를 말하는 유일한 채널이다. 포커스 표시(`*:focus-visible` 전역 링)도 그대로 살아 있어야 한다(WCAG 2.4.7).
- 「종목명 클릭 → 검색」은 **이미 그렇게 동작한다**(버튼 전체가 `onClick={() => setSearching(true)}`). 새로 만들 것이 없다 — **확인만 하고 보고**해라. 260912-mvo 가 `flex-1` 을 걷어 「종목명에서 떨어진 허공」이 눌리지 않게 한 상태이고, 그 범위(종목명+코드+아이콘)가 사용자가 원한 그것이다. **`flex-1` 을 되살리지 마라.**
- 높이 `h-9`(36px)는 **그대로다** — 거래소 콤보·검색 입력과 같은 줄에 같은 키로 서게 한 값이고, 풀면 헤더 한 줄이 상태 전환마다 튄다(260912-ok2 ④, WINDOWS 8).

## ④ 체크박스가 꺼져 있어도 입력은 되게

사용자: 「매수옵션 체결인풋, 매도옵션 잔량추적·체결, 취소옵션 잔량 등에 체크박스가 꺼져있어도 입력은 되게해줘. 취소옵션 안켜도 취소옵션의 체결, 잔량추적은 킬 수 있게 해줘.」

`limit-chaser-form.tsx` 에서 **정확히 5곳**이다(전수 확인 완료 — `disabled || !form.` 패턴):

| 줄 | 대상 |
|---|---|
| 730 | `disabled={disabled \|\| !form.buyTradeQtyEnabled}` — 매수 체결 수량 입력 |
| 840 | `disabled={disabled \|\| !form.sellQtyTrackEnabled}` — 매도 잔량추적 입력 |
| 859 | `disabled={disabled \|\| !form.sellTradeQtyEnabled}` — 매도 체결 입력 |
| 919 | `disabled={disabled \|\| !form.cancelQtyEnabled}` — 취소 감시 잔량 입력 |
| 938~939 | `disabled={disabled \|\| !form.cancelQtyEnabled}` + `dimmed={!form.cancelQtyEnabled}` — 취소 **잔량추적 체크박스** |

전부 `!form.xxx` 항을 없애고 **전역 `disabled` 만** 남긴다. 938 의 `dimmed` 도 없앤다(더 이상 비활성이 아닌데 흐리면 거짓말이다).

- ★ **페이로드 계약은 바뀌지 않는다.** `cancelQtyTrackEnabled` 는 `lib/limit-chaser.ts` 에서 이미 독립 필드로 서버에 나간다(129·132·284·287). UI 결합만 풀리는 것이고, 게이트웨이가 모르는 조합을 만들어 내지 않는다.
- ★ **무장 판정(`lib/limit-chaser.ts:171` 부근의 게이트 4종)은 손대지 마라.** 「취소잔량이 꺼져 있으면 취소는 무장하지 않는다」는 서버 쪽 의미이고, 이번 변경은 **입력 가능 여부**만 바꾼다. 둘을 섞으면 사용자가 값을 넣었는데 전략이 조용히 다르게 도는 상태가 된다.
- 936 의 주석(「취소 잔량추적은 **취소잔량과 함께만** 동작한다 — 미체크면 비활성(A9)」)은 이제 거짓이다. **갱신**해라 — UI-SPEC A9 의 결합을 사용자가 명시적으로 풀었다는 사실과, **그럼에도 무장 판정은 그대로**라는 구분을 남겨라.
- 이 결합을 잠그고 있는 기존 단위 테스트가 있으면 **새 계약으로 다시 쓴다**(단언 삭제 0건). 없애지 말고 반대 방향으로 잠가라 — 「체크가 꺼져도 입력이 활성이다」.
