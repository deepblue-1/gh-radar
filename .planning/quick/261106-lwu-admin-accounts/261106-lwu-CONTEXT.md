# 어드민 계좌 메뉴 · 사용자별 계좌 연결 — 결정 (잠금)

## 배경
지금은 `/admin/users` 사용자 시트의 「계좌 · 등록 서버」(`AccountEditor`)에서 계좌번호·지점·트레이더를 직접 입력해
사용자(DMA id)마다 계좌를 추가한다. 같은 계좌를 여러 DMA 사용자가 쓰면 각 사용자에 따로 입력된다.
→ 계좌를 독립 목록(마스터)으로 관리하고, 사용자 시트에서는 그 목록에서 골라 **연결**만 한다.

## 결정 D-01 ~ D-10 (목업 정본 — 화면 모양은 목업을 따른다)

- **D-01 새 메뉴 `/admin/accounts` 「계좌」.** 사이드바 Admin 하위 순서 = 사용자 · **계좌** · 서버 · 발사 · 매매손익.
  어드민만(기존 `/admin` 접두 middleware · Express `requireAdmin` 그대로).
- **D-02 사이드바 순서 교체:** 지금 「… 분석 · Admin · My page」 → **「… 분석 · My page · Admin」**.
- **D-03 계좌 마스터가 갖는 값 = 계좌 자체 정보만:** 증권사 · 계좌번호(키 — 등록 뒤 못 바꿈) · 계좌명 · (KB) 지점 5자 · 트레이더 6자.
  교보는 지점·트레이더 없음(기존 CHECK 규칙 그대로). 계좌번호 정규화는 shared `normalizeAccountNo` 한 벌.
- **D-04 연결별 설정은 사용자 시트에 그대로 남는다:** 등록 서버 · 주문 서버 · 주문자 IP/MAC · 예수금 · 수수료 · 매도세 —
  지금 `AccountEditor` 카드의 동작·쓰기 경로를 바꾸지 않는다.
- **D-05 기존 계좌 백필:** 지금 `dma_user_accounts` 의 계좌를 (broker, account_no) 로 묶어 마스터에 한 번 옮긴다.
  여러 사용자가 같은 계좌를 가지면 한 줄(값이 다르면 `updated_at` 최신 행 값). 마이그레이션은 멱등.
- **D-06 계좌 목록 화면(목업 ①):** 헤더 「계좌」 · 부제 「관리 계좌 등록 · 수정 · 삭제 — 사용자에게 연결은 「사용자」 메뉴에서」 ·
  「+ 계좌」 · 증권사 필터 세그먼트(전체·KB·교보 + 개수) · 행 = 증권사 배지 · 계좌번호 · 계좌명(빈 값 흐린 「이름 없음」) ·
  지점·트레이더(교보 「해당 없음」) · 「쓰는 사용자」 DMA id 칩들 또는 점선 「연결 없음」 · `›`. 행 클릭 → 오른쪽 시트(사용자 화면의
  `AdminPanelPage` 비모달 패턴 · 폰은 전체 화면).
- **D-07 등록 시트(목업 ②):** 증권사 세그먼트 · 계좌번호 · 계좌명(선택) · KB 면 지점·트레이더. **등록만으로는 증권사 서버에 아무것도
  보내지 않는다**(DB 마스터만). 중복(같은 증권사·정규화 계좌번호) 409 → 칸 아래 오류 한 줄.
- **D-08 수정 · 삭제 시트(목업 ③):** 증권사·계좌번호 읽기 전용. 계좌명·지점·트레이더 저장 = 마스터 갱신 + **연결된 모든 DMA 사용자에게
  기존 계좌 PUT 경로로 같은 값 반영**(각 사용자의 지금 active 등록 서버 그대로) → 「쓰는 사용자」 목록에 사용자·서버별 결과 칩
  (기존 `ResultChips`/`BusyLines` 문구 재사용 — 실패는 서버 message 원문). 삭제는 **연결된 사용자가 0명일 때만** — 있으면 버튼 비활성 +
  「연결된 사용자가 있어 삭제할 수 없어요 — 「사용자」 에서 먼저 연결을 해제하세요」, 서버도 409 `ACCOUNT_IN_USE` 로 막는다.
  연결 0명이면 시트 안 확인 박스(「…삭제할까요? 목록에서 사라지고 되돌릴 수 없어요」 · 취소/삭제) — 브라우저 confirm 금지.
- **D-09 사용자 시트 계좌 영역(목업 ④ · 연결 방식 A 채택):** 「+ 계좌 추가」(직접 입력 폼 `AccountAddForm`) →
  **「+ 계좌 연결」 피커**: 검색칸(계좌번호·계좌명) + 이 DMA 사용자에 아직 없는 마스터 계좌 목록(라디오 · 행 오른쪽에 쓰는 사용자 DMA id
  또는 「연결 없음」) + 고른 계좌 증권사의 등록 서버 체크(기본 체크 없음 · 꺼진 서버 비활성 — 지금 규칙 그대로) + 취소/연결 +
  「목록에 없으면 「계좌」 에서 등록」 링크. 연결 = 기존 `PUT /dma-users/:dma/accounts`(값은 마스터 값).
  카드의 「제거」 → **「연결 해제」**(동작은 기존 DELETE 그대로 — 마스터는 남음 · 마지막 계좌 해제 = 사용자 삭제 확인 흐름 그대로).
  카드 편집 모드에서 **계좌명 입력칸은 뺀다**(계좌명은 계좌 메뉴에서만). KB 는 IP/MAC 편집 그대로, 교보는 편집할 것이 없으므로 「편집」 숨김.
  카드 메타 줄에 「계좌명 · 지점 · 트레이더는 「계좌」 메뉴에서」 안내.
- **D-10 사용자 만들기 · DMA 연결의 「첫 계좌」(목업 ⑤):** `DmaConnectFields` 의 증권사·계좌번호·지점·트레이더 입력칸 → D-09 와 같은
  피커(A · 마스터 전체 · 연결/취소 버튼 없이 선택값만 부모로) + 등록 서버 체크. 생성 바디 모양(`AdminDmaInput.account`)은 그대로 —
  값을 마스터에서 채운다.

## 서버측 정합 규칙
- 연결(사용자 PUT · 사용자 생성 dma · DMA 연결 POST)은 **마스터에 있는 계좌만** 허용 — 없으면 409 `ACCOUNT_NOT_REGISTERED`.
  값(계좌명·지점·트레이더)은 마스터 값을 정본으로 쓴다(웹이 보낸 값과 달라도 마스터 값).
- `dma_user_accounts` 의 name/branch_no/trader_id 열은 relay planner 가 읽으므로 **남긴다** — 마스터 수정 시 연결 행도 같이 갱신(D-08 팬아웃).
- relay 코드 변경은 피한다(가능하면 0). 새 테이블은 RLS on · anon/authenticated 정책 없음 · RPC 를 쓰면 `REVOKE … FROM anon, authenticated` 명시.

## 범위 밖
- 계좌별 IP/MAC·예수금을 마스터로 옮기기 · 계좌 메뉴에서 사용자 연결/해제 · 계좌번호 변경 · `/admin/pnl` 등 다른 화면의 계좌명 출처 변경.
