# Sketch 019: 틱 전문 뷰어 배치

## Design Question
Phase 37 — KRX·NXT 어느 종목이든 08:00~20:00 의 틱 단위 전문(호가 B6 · 체결 A3 · 거래원 B9 · VI R8 · 프로그램 C3)을 실제 수신 순서대로 재생하는 뷰어. 로드맵 성공 기준 1 「슬라이더 · 점프 · 좌우 키 · 호가창 · 전문 목록 · 버스트 · 거래대금 · 팀 패널 배치」 를 A/B/C 로 고른다. 참고 스크린샷(사용자 ATMParser · 행 = 전문 하나)은 전문 목록 패널에만 살리고 호가창은 사다리형으로 분리한다(로드맵 정본).

데이터는 한선엔지니어링(101360) 2026-10-22 를 본뜬 생성 데이터다 — 09:00 15,550 에서 09:02:41 정적 VI 발동(16,300) · 09:04:41 해제 뒤 09:08 17,100 벽까지 급등, 이후 보통 거래 · 15:30 종가 · 16:10~18:00 시간외 단일가. 전문 약 4천 건. 주문 묶기 · 팀 판정은 gh-trade 정본대로 — 같은 종목 A3 msg_seq 직전 +1 · bs 동일이면 한 주문, 모양 A 자전거래방지 SMP(한 가격 2조각+) ∪ B 0/0 단독 = 팀, C0(단마다 1조각 · 끝까지 0/0) 과 나머지는 일반, 단일가 제외(`krx-a3-zero-quote.md` §2·§4 · `team-flow.md` §4). 팀 손익은 평균단가법(§5-1). 닫는 B6 가 마지막 A3 조각보다 먼저 수신되는 역전(다른 멀티캐스트 그룹)을 12% 심었다.

## How to View

맨 위 버튼으로 배치(A/B/C) · 폭(데스크톱 1280 / 폰 390) · 테마 · 공급(과거 격자 / 당일 요청형)을 고른다. 모든 변형에서 공통으로 동작한다:
- 하단 슬라이더 드래그 · 시각 입력(`HH:MM:SS.mmm`) 뒤 Enter 또는 「점프」 · `←` `→` 한 틱 · `Shift+←/→` 10틱 · `Space` 재생.
- 전문 목록 행 클릭 = 그 틱 선택. 선택 틱과 같은 주문(런)의 행은 옅은 보라 띠, 팀 주문 행은 왼쪽 보라 선.
- 「수신순 | 거래소순」 토글. 수신순에서 역전된 B6 는 `↕ 수신 역전` 표시(상세 표현은 020 에서).
- 호가 10단은 선택 틱 시점의 마지막 B6(msg_seq 순) 재구성. 체결 틱이면 그 가격 행에 점과 테두리. 패널 머리 「주 | 금액」 토글로 잔량을 금액(잔량 × 호가 · 스케치 010 C 축약 표기 억·만 · 주수 병기 없음)으로 바꾸고, 바닥 줄은 「총잔량」 ↔ 「합산 금액」 으로 같이 바뀐다. 바 길이도 보는 단위를 따른다(2차 검토 요청).
- 「당일 · 요청형」 은 배지 · 날짜 · 「끝으로」 버튼만 바뀐다(데이터는 같음).

## Variants
- **A: HTS 3단** — 왼쪽 호가 10단, 가운데 전문 목록, 오른쪽에 이 주문(버스트) · 거래대금 · 팀 거래정보 카드를 세로로. 하단 전폭 슬라이더(5분 거래대금 밀도 · VI 주황 눈금). 한 화면에 전부 있고 접히는 것이 없다. 폰은 「호가 | 전문 | 버스트 · 팀」 세그먼트로 하나씩.
- **B: 타임라인 주인공** — 상단에 하루 타임라인(5분 거래대금 막대 · 가격선 · VI 띠 · 팀 버스트 눈금 · 현재 시각 커서)과 ±30초 확대 줄(체결 막대 = 수량, 매수 빨강 · 매도 파랑 · 팀 보라 · B6 회색 · R8 주황). 둘 다 클릭하면 점프. 아래는 호가 | 전문 목록이고 버스트 · 팀은 전문 패널의 탭. 거래대금 · 팀 요약은 타임라인 머리의 칩.
- **C: 전문 스트림 중심(모바일 우선)** — 전문 목록 한 열이 본문(데스크톱 760 가운데 정렬). 팀 순매수 · 평단 · 거래대금 · 현재가는 상단 칩. 행을 누르면 호가창 · 이 주문 · 거래대금이 데스크톱은 오른쪽 드로어, 폰은 바텀시트로 열리고 `←` `→` 로 넘겨도 열린 채 따라온다. `Esc`/✕ 로 닫는다.
- **D: 종합 A+B(매집 차트)** — 1차 검토(2026-11-02) 사용자 요청 「A 와 B 를 섞되 타임라인에는 매집감지 보고서의 차트 내용」. 위에 매집감지 상세 3판 차트(`accum-chart.tsx` 레이어 순서 — 가격 선 · 팀 평단 `--up` 점점선 · 팀 주문 원 ≥500만원(매수 빨강 · 매도 파랑 · 크기 = 금액) | 당일 팀 순매수 보라 계단(오른쪽 보라 축) + 누적 순매수 회색 계단(이월 포함 · 왼쪽 회색 축 · 0 포함 독립 범위 — 스케치 018 ② 그대로 · 2차 검토 요청으로 추가) · 0선 | 10분 팀 매수/매도 막대 쌍)에 VI 띠 · 15:30~16:00 빈 띠 · 장전 음영 · 현재 틱 커서(세 판 관통 + 시각 라벨)를 얹었다. 휠 = 확대/축소 · 끌기 = 이동 · 클릭 = 점프 · `+` `−` `0` 키 · 「1분」「10초」 버튼 · 틱이 창 밖으로 나가면 창이 따라간다. 주문 원 클릭 = 그 주문 마지막 조각. 호버 툴팁(시각 · 가격 · 당일 순매수 · 누적(이월 포함) · 평단). 슬라이더(재생 · 시각 입력 · 점프)는 3차 검토 요청으로 차트와 호가 · 전문 사이에 카드로 놓였다 — 차트 커서와 슬라이더 손잡이가 같은 시각을 가리키며 붙어 있다. 아래는 A 그대로. 누적 선의 이월 +12.4억은 가정값 — 실제는 매집감지 export `payload.pos_net`(gh-trade)에서 읽어야 하며 틱 데이터만으로는 못 그린다(Phase 37 계약 항목).

## What to Look For
- **급등 구간(09:05~09:08)에서 ← → 를 연타할 때** 눈이 어디를 봐야 하는지 — A 는 셋이 동시에 바뀌고, B 는 확대 줄 커서가 움직이고, C 는 목록 선택만 움직인다(드로어 열면 둘).
- **VI 구간(09:02:41~09:04:41)** — B6 만 흐르고 호가 메타에 「VI 중」. 09:04:41 해제 직후 단일가 체결(A3 bs 0 · 「단일가」 칩 · 주문 묶기 제외)이 세 배치에서 어떻게 읽히나.
- **팀 주문(SMP ×n)** 의 마지막 조각을 고르면 「이 주문」 카드가 조각 · 단 · 수량 · 금액 · 지속(µs/ms) · 닫는 B6 seq 를 보여 준다. 역전 주문이면 주황 `↕`. 최근 주문 10건 표에서 행을 누르면 그 주문으로 점프.
- **팀 거래정보** 의 두 해상도 — 위 KPI 는 A3 평균단가법(틱마다 바뀜), 아래 5창구 표는 마지막 B9 스윕(≈1분마다 바뀜). 최소치 캡션이 눈에 거슬리지 않는지.
- **슬라이더 12시간 폭** — 09:00~09:10 10분이 전체의 1.4% 라 슬라이더로는 초 단위에 못 간다. 시각 입력 · 키 이동 · (B 의) 확대 줄 · (D 의) 차트 확대 가운데 무엇이 「ms 점프」 역할을 맡아야 하는지.
- **D 에서 볼 것** — 하루 전체에서 09:00~09:10 급등의 주문 원 · 보라 계단이 읽히는지, 「1분」으로 좁혔을 때 ← → 로 틱을 넘기며 커서가 원 사이를 지나가는 느낌, 3판 높이(데스크톱 230 · 폰 165)가 아래 HTS 3단을 너무 누르지 않는지(데스크톱 프레임 880), 폰에서 3판 + 세그먼트가 과한지. 보고서 차트와 같은 모양이라 두 화면을 오가도 눈이 재학습하지 않는지.
- **폰 390** — A 는 세그먼트 3개, B 는 타임라인이 84px 로 줄고 세그먼트 2개, C 는 바텀시트 70%. 호가창을 보면서 전문을 넘길 수 있는 배치는 데스크톱뿐인데 폰에서 그것이 필요한지.
- 다크 · 라이트 모두 체결 수량 색(매수 빨강 · 매도 파랑) · 팀 보라 · VI 주황이 구분되는지.

## Decision (2026-11-02)
- **D 종합 A+B 채택** — 4차 검토 끝. 위에서 아래로: 머리(종목 · 날짜 · KRX|NXT · 공급 배지 · 현재 틱 시각/seq) → **매집감지 3판 차트**(가격 선 · 팀 평단 `--up` 점점선 · 팀 주문 원 ≥500만 | 당일 팀 순매수 보라 계단(오른쪽 보라 축) + 누적 순매수 회색 계단(이월 포함 · 왼쪽 회색 축 · 0 포함 — 스케치 018 ② 동형) | 10분 팀 매수/매도 막대 쌍 · VI 띠 · 15:30~16:00 빈 띠 · 장전 음영 · 현재 틱 커서 + 시각 라벨 · 휠/끌기/클릭/`+ − 0`/「1분」「10초」 · 틱이 창 밖이면 창이 따라감 · 주문 원 클릭 = 그 주문 마지막 조각) → **슬라이더 카드**(‹ ▶ › · 08~20 슬라이더(5분 거래대금 밀도 · VI 눈금) · 시각 입력 + 점프 · 당일이면 「끝으로」) → **HTS 3단**(호가 10단 · 전문 목록 · 이 주문 | 거래대금 | 팀 거래정보). A/B/C 는 하단 슬라이더였고 D 만 차트 바로 아래다.
- **호가 10단 「주 | 금액」 토글** — 금액 = 잔량 × 호가 · 스케치 010 C 축약 표기(억 · 만 · 주수 병기 없음) · 바닥 줄 「총잔량」 ↔ 「합산 금액」 · 바 길이도 단위를 따른다. C 드로어 포함 모든 호가 패널 공통.
- **차트의 누적 순매수(이월 포함)는 틱만으로 못 그린다** — 매집감지 export `payload.pos_net`(gh-trade)을 뷰어가 함께 읽어야 한다. Phase 37 discuss/계약 항목으로 넘긴다(이 스케치의 이월 +12.4억은 가정값).
- 폰(390): 3판 차트 165px(제목 글자 생략) + 슬라이더 카드 + 「호가 | 전문 | 버스트 · 팀」 세그먼트 하나씩. 폰에서 3판이 과한지는 실기기에서 다시 본다(미결).
- 전문 목록 행 · 순서 뒤집힘 · 버스트 묶음 표현은 스케치 020.

## 미결 (이 스케치에서 정하지 않음)
- 전문 목록 행 상세 — 수신순↔거래소순 뒤집힘 표현(토글 / 행 안 표시 / 둘 다), 버스트 묶음 표현(행 그룹 / 요약 행 접기 / 배지) → 스케치 020.
- NXT 토글은 라벨만 바뀐다(생성 데이터는 KRX 하나). NXT 체결의 호가 공백 규칙은 gh-trade 와 계약 때 확인.
- 당일 요청형의 「수 초 지연」 표현(끝 틱 뒤 수신 대기 상태)은 배치 결정 뒤 실제 응답 모양이 나오면.
