# Sketch 006: 로그인 화면

## Design Question
현재 `/login` 은 shadcn Card 가운데에 「GH Trade에 로그인」 + 「Google 계정으로 로그인하고 관심종목을 저장하세요」 + Google 버튼. 설명 문구를 없애고 브랜드(앱 아이콘 A 다크 레이더 · 워드마크)와 버튼 하나만으로 화면을 세울 때 어느 구성이 맞는가. 웹(데스크톱 1280)과 앱(iPhone 390) 에서 함께 본다.

## How to View
open .planning/sketches/006-login-screen/index.html

상단 바: 변형(A/B/C) × 기기(iPhone 은 다크·라이트 나란히 / 데스크톱은 테마 토글) × 상태(기본 / 오류 / 진행 중). 버튼을 누르면 1.3초 스피너 후 이동 토스트(가짜 로그인).

## Variants
- **A: 비움** — 카드 없음. 앱 아이콘 76(radius 22%) + 워드마크 26/800 이 화면 가운데, Google 버튼 56 이 폰 하단(좌우 20 · 바닥 44) / 데스크톱은 워드마크 아래 360 폭. 문구 0. 만들 것이 가장 적다.
- **B: 레이더** — 화면 전체에 동심원 5개(`--fg` 7~12%) + 7초에 한 바퀴 도는 붉은 스윕(`#f04452` 28%, 라이트 20%) + 중심 점. 폰은 하단 시트(`--card` radius 28 상단) / 데스크톱은 가운데 카드 420 에 워드마크 24 + 버튼. 앱 아이콘 모티프의 확대.
- **C: 시세** — 폰 상단 52% / 데스크톱 좌측 56% 가 항상 짙은 패널(`#17171c`, 테마 무관) — 아이콘 44/52 + 오늘 급등 종목 카드(종목명 · 현재가 · 등락률 · 「상한」 배지)가 폰에서는 옆으로 흐르고 데스크톱은 3장 세로. 아래/우측 `--bg` 면에 워드마크 26/30 + 버튼 340. 실데이터(scanner 상위) 연결 가능.
- 공통: Google 버튼은 다크에서 흰 바탕 + `#191f28` 글자, 라이트에서 `#191f28` 바탕 + 흰 글자(반전 CTA, 56 · radius 16 · 16/700). 오류는 버튼 위 `--up-bg`/`--up` 알림 12px radius. 진행 중은 스피너 + 70% 불투명.

## What to Look For
- 문구 없이 「무슨 앱인지」가 전달되는가 — A 는 아이콘·이름만, B 는 무드, C 는 실제 콘텐츠.
- 라이트 모드에서 각 안이 살아 있는가 — B 의 붉은 스윕이 흰 바탕에서 과한지, C 의 다크 패널이 라이트 앱과 이질적인지.
- 데스크톱에서 빈 공간 — A/B 는 화면이 넓을수록 비어 보이고, C 는 채워진다.
- 오류 상태에서 레이아웃이 튀지 않는가(A 는 버튼 위로 밀림, B/C 도 동일).

## 결정 (2026-09-26)
- **A 비움 채택.** 카드·제목·설명 문구 모두 제거. 화면 = 앱 아이콘 A(다크 레이더, 76 · radius 22%) + 워드마크 「GH Trade」 26/800 letter-spacing −.03em 을 세로 가운데(gap 22) · Google 버튼 56 · radius 16 · 16/700 을 폰 하단(좌우 20 · 바닥 44 + safe-area) / 데스크톱은 워드마크 아래 360 폭. 버튼 색은 반전 CTA — 다크 `#ffffff`/`#191f28`, 라이트 `#191f28`/`#ffffff`. 오류는 버튼 위 12px `--up-bg`/`--up` 알림(기존 4종 문구 유지) · 진행 중은 스피너 + 70%.
- 앱(Phase 21)은 Remote-URL 셸이라 운영 웹 `/login` 을 그대로 렌더한다 — 웹 한 번 고치면 앱도 같은 화면. 네이티브 id_token 로그인 로직은 그대로, 시각만 바뀐다.
- 과정: 1차 렌더에서 버튼 라벨 `.lb` 가 변형 B 컨테이너 `.lb` 와 충돌해 버튼이 안 보이던 결함 · 변형 C 라이트 폰 상태바 글자 색 결함을 고친 뒤 검토.
