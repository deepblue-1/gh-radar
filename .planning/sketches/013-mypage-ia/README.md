# Sketch 013: /me 마이페이지 정보 구조

## Design Question
현행 `/me` 는 계정 카드 → 상태줄 → **상따 기본설정(11행 전부 펼침)** → 전략 현황 → 계좌별 미체결·잔고 → 오늘 주문이 한 세로 열에 다 쌓인다.
매매조건 설정이 전략·잔고 위에서 자리를 많이 먹고, 봐야 할 표면이 많아 어느 것도 빨리 읽히지 않는다. 어떤 구조로 나눌까.

## Variants
- **A: 상단 4탭** — 계정 카드 아래 「현황 · 잔고 N · 주문 N · 설정」 탭(종목상세 4탭 문법). 한 번에 한 표면. 매매조건은 「설정」 탭 — 묶음 4개가 카드로, 데스크톱 2열.
- **B: 접힘 요약 세로** — 세로 순서 유지. 카드마다 한 줄 요약 머리 + 접기. 기본 전략·계좌 펼침, 오늘 주문·매매조건 접힘(요약 「선 100만 · 추 50만 · 후 30만 · 매도 5초」). 열면 그 자리에서 편집.
- **C: 요약 타일 + 설정 분리** — 상단 KPI 타일 4개(켜진 전략 · 미체결 · 보유 · 오늘 주문), 데스크톱 2열(전략·오늘 주문 / 계좌). 매매조건은 하단 「설정」 메뉴 행 → 별도 페이지 `/me/settings`(테마·로그아웃도 메뉴로).

## Data
예시값. 전략 3(무장·대기·후매수 대기) · 계좌 2(위탁종합 12345678-01 · CMA 98765432-02) · 미체결 2 · 보유 3 · 오늘 주문 7 · 설정 11값은 Phase 27 목업 값.

## Decision (2026-10-06)
- **A 상단 4탭** 채택 — 계정 카드 아래 「현황 · 잔고 N · 주문 N · 설정」, 종목상세 4탭과 같은 `?tab=` 메커니즘. 현황 = 상태줄 + 전략 현황 · 잔고 = 계좌별 미체결·잔고 · 주문 = 오늘 주문 · 설정 = 상따 기본설정.
- 설정 탭 행 모양 **S1 묶음 카드 4장** 채택(`settings.html`) — 묶음마다 카드, 행은 SettingRow·ChoiceRow 44px 그대로, 데스크톱 2열. S2(한 장)·S3(값 타일) 기각.
