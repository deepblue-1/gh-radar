⚠ Pretendard 가 아직 안 실렸어요 — 수치가 실제 앱과 다를 수 있어요

대상은 종목상세 호가주문 탭의 OrderbookStatusBar(stock-orderbook-section.tsx)예요 — DMA · 계좌 · 거래소 KRX|NXT · 래치 LED 3칩 · 구간 배지 · (거부) · 반영 시각. 지금은 flex-wrap 이라 좁으면 여러 줄로 접혀요. 아래 변형은 글자를 자르거나 말줄임하지 않고(라벨 잘림 0 = 오발주 불변식) 배치를 바꿔서만 줄여요. 모든 변형은 안전망으로 flex-wrap 을 유지해서, 안 들어가면 잘리는 대신 2줄로 떨어져요.

최악값: 계좌 1234567802 · 개인연금저축(네이티브 select 는 가장 긴 옵션 폭을 차지) · LED 매수 감시 / 매도 대기 / 취소 대기(전부 클릭 가능 = 굵은 글자) · 구간 「예약구간 · 조각 최대 10」 · 거부 「[상따] 주문 가능 금액이 부족합니다」. 거부와 미반영은 동시에 서지 않아요 — 코드가 거부를 받으면 미반영을 거둬요(strategy-card.tsx 「거부도 답이다」). 그래서 시나리오를 ①·②로 나눴어요. ③은 회선 끊김(가장 긴 연결 문구 + 「다시 연결」).

판정(브라우저가 지금 잰 값): 상태줄 안 항목들의 세로 위치를 묶어 줄 수를 세요(항목 안에서 글자가 접힌 줄도 더해요). 「1줄 ✓」 = 한 줄 · 「N줄」 = 목표 미달(잘림은 아님) · 「넘침 −Npx」/「잘림」 = 불변식 위반(빨간 테두리). 잘림은 select 가 자기 글자 폭보다 좁아졌는지(격리 복제 폭과 비교)와 항목이 상태줄 안쪽 가장자리를 넘는지로 봐요. 파란 점선 = 상태줄에서 아래 고지 줄로 옮겨 간 것.
