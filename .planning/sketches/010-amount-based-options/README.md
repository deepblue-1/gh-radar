# Sketch 010: 상따 옵션·호가 잔량 금액 환산

## Design Question
Phase 24 상따 옵션 중 **주(株) 단위 필드**(선매수 매도잔량·체결량, 추가매수 최소/최대 잔량, 후매수 최소 잔량·발동잔량,
매도 호가잔량·체결, 취소잔량)를 전부 **금액(만원 단위)** 으로 세팅하고, 호가창의 매도/매수 잔량도 **잔량 × 호가 = 금액**으로
환산해 보여준다. 1차는 삼성전자(조 단위)로 극단을 봤고, 2차(사용자 피드백)부터는 상따 실사용 규모인
**시총 약 1,000억 가상 종목 「가온테크 123450」**(기준가 7,200 · 상한가 9,360 · 현재가 9,350) 상한가 근접 호가로 바꿨다. **어떤 금액 표기**가 좁은 폰 열(42% ≈ 164px)·태블릿 260 열·데스크톱 3단 440 열에서 읽히는지를 비교한다.

환산 기준가(목업 규약):
- 잔량·체결 임계 금액 → 주수 = 금액 ÷ **비교가격**(매수 쪽 `buy_watch_price`, 매도·취소 쪽 `sell_watch_price`) — 조건은 그 가격에서 판정되므로.
- 그룹 주문 금액 → 주수 = 금액 ÷ **주문가격**(기존 `QtyFromAmount` 규약 그대로).
- 호가창 잔량 금액 = 잔량 × **그 호가 가격**.
- 서버가 주로 내려주는 값(발동잔량 `post_buy_trigger_qty`)은 비교가격으로 금액 환산해 표시(주수 병기 토글을 켰을 때만 주수).
- 환산 기준가는 화면에 쓰지 않는다 — 카드 안 안내 문구는 행 정렬을 깨뜨려 보여 제거(사용자 결정 2026-09-27). 시트의 「= 원 · ≈ 주 @가격」 미리보기가 유일한 환산 노출.

행을 누르면 폰·태블릿은 만원 키패드 시트(+100만/+1,000만/+1억/+10억 칩 · 원·주 환산 미리보기), 데스크톱은 인라인 편집(≈주수 실시간).

## Variants
- **★ C: 축약 (winner, 2026-09-27)** — 유효 3자리 「7.96억」·「19.5억」·「3,000만」. 가장 짧다. 정밀값은 시트 미리보기에서. 주수 병기는 끈다.
- **A: 만 고정** — 모든 금액을 만원 단위 정수로(「100,000만」= 10억). 입력 단위 = 표시 단위, 자릿수로 크기 비교. 조 단위는 「132,600,000만」으로 길다.
- **B: 억·만 혼합** — 「2,011억 1,000만」·「1조 3,260억」. 관례대로 읽히지만 글자 수가 가변이라 폰 호가 칩이 두 줄.

## What to Look For
- 폰 390 호가(42% 열)에서 A/B/C 칩이 **한 줄에 드는가**, 가격 열이 밀리지 않는가.
- 데스크톱 3단(440)에서 좌 매도금액 / 우 매수금액 바와 숫자가 **가격 축 기준으로 대칭**으로 읽히는가(현행 사다리 규약).
- 「주수 병기」를 켰을 때 두 줄 행(48px)이 답답한가, 껐을 때 잔량 감(주)이 사라져 불안한가.
- 옵션 행 「매도잔량 ─ 5,000만 ›」 — 주수 보조가 필요한가, 금액만으로 충분한가.
- 시트의 단위 칩(+100만 … +10억)이 만원 입력을 빠르게 하는가.

## 2차 (2026-09-27, 사용자 피드백)
- C 축약 채택 · 주수 병기 기본 꺼짐.
- 카드 안 환산 기준 안내 문구 전부 제거(행 정렬이 어긋나 보임).
- 종목을 삼성전자 → 시총 약 1,000억 가상 종목으로, 시세는 상한가 근접 하나만(평상시 토글 제거).
