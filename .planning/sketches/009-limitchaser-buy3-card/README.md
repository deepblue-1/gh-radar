# Sketch 009: 상따 매수 카드 3그룹

## Design Question
gh-trade Phase 24 로 상따 매수가 **선매수·추가매수·후매수** 세 갈래가 됐다(마스터 `buy_enabled` + 그룹별 `*_enabled`,
주문가격·비교가격은 공통, 금액은 그룹마다). WinForms 창(`../../phases/24-limitchaser-buy3/reference/winforms-limitchaser-options-2026-09-27.png`)은
한 패널에 체크 줄 + 점선 구분이다. 웹의 현행 문법(002-B: 카드 = 제목줄+스위치, 행 = 「라벨 ─ 값 ›」 44px, 체크 행 「○ 라벨 ─ 값 ›」,
폰 시트 / 데스크톱 인라인)에서 이 셋을 **어느 카드 구조**로 담을지 세 변형을 비교한다.

## Variants
- **★ D: 종합 — A 구조 + 접기 (winner, 사용자 확정 2026-09-27 — 기본 전부 접힘 · 접기 트리거 = 제목줄 전체, 스위치만 예외)** — 카드 3장은 A 그대로. 제목줄을 누르면 카드가 접히고(스위치는 그대로 동작), 접힌 카드는 제목줄 아래 **요약 줄**에 값이 전부 보인다(금액 · 매도잔량 · 체결량 · 한방 / 금액 · 최소 · 최대 / 금액 · 최대 N회(남은 k회) · 최소 · 반등 · 발동잔량). 여러 줄이 돼도 잘리지 않고 줄바꿈. 펼치면 요약이 사라지고 A 모양의 행이 나온다. 기본은 전부 접힘 — 폰에서 매수 탭이 한 화면에 든다.
- **A: 카드 3장** — 「매수주문」 카드(주문가격·비교가격·마스터 스위치) 아래 선매수·추가매수·후매수 카드가 각각. 그룹 스위치는 제목줄 오른쪽(기존 카드 문법 그대로). 폰에서 가장 길다.
- **B: 한 카드 · 체크 행** — WinForms 충실. 「매수주문」 카드 하나 안에 주문가격·비교가격 → 점선 → **「○ 선매수 ─ 10만원 ›」 체크 행**(체크 = 그룹 켜기 · 값 = 그룹 금액) + 하위 행 → 점선 → 추가매수 → 후매수. 꺼진 그룹의 하위 행은 흐리되 편집 가능(WinForms 규약). 후매수 상태 칩은 체크 행 안.
- **C: 접힘 요약** — 「매수주문」 카드 안에 그룹마다 56px 요약 행(이름 · 상태 칩 · 값 요약 한 줄 · 스위치). 행을 누르면 하위 행이 펼쳐지고, 꺼진 그룹은 요약 한 줄로만 남아 폰에서 가장 짧다.

## 세 변형 공통(동작 규약 — gh-trade 인계 §3)
- 마스터 OFF → 세 그룹 체크가 함께 꺼져 에코된다(D-32, 2026-09-27 gh-trade 결정 — 인계문 §6 「열린 것」 첫 항은 닫혔다).
- 그룹 ON 인데 마스터 OFF → 같은 제출에 마스터도 켬(WinForms 24-06 규약, 로그 「{그룹} 체크 — 매수주문도 켬」). **웹도 따를지는 결정 항목.**
- 선매수 ON → 매도주문·매도>잔량추적·매도>체결·취소·취소>체결·취소>잔량추적 6개 자동 체크 + 토스트/로그(D-06, 확인창 없음). 매도 탭에서 결과 확인.
- 추가매수 ON 시 최대≠0 ∧ 최소>최대 → 체크 불가 + 행 아래 빨간 안내(D-10). 후매수 ON 시 매도비율 0 → 체크 불가 + 안내(D-27). 「매도비율 0」 버튼으로 재현.
- 후매수 상태: 체크 행/제목줄 칩 「감시 중 / 보유중 / 소진」 + 읽기 전용 「발동잔량」 행(없으면 —, 있으면 빨강) + 「최대」 칸은 단계≠0 이면 서버 잔여(「남은 2회」) 표시, **제출값 = 칸 값**(D-30·31). 소진이면 체크 OFF + 「남은 0회」 + 안내 한 줄.
- 후매수 발동(보유중) → 매도·취소 자동 무장 에코: 매도 탭 매도주문·매수취소 ON, 호가잔량·취소잔량 = 발동잔량(D-13). 상단 LED 「매수」 = 마스터 2단계(OFF 회색 / 감시 초록) + 보유중 주황.
- 추가매수 포기 → 체크 OFF + 칩 「포기」(재제출 전까지 안 삼).
- 전략 로그 4줄(패널 아래): 사유 줄 원문(`후매수 — 매수1잔량 N > 발동잔량 T` · `후매수 소진 — 잔여 0회` · `추가매수 포기 — …`).

## What to Look For
- **D:** 접힌 요약 줄이 「한눈에 값 확인」으로 충분한가 · 제목줄 클릭 = 접기(스위치와 분리) 가 헷갈리지 않나 · 기본 접힘이 맞나(켜진 그룹은 펼쳐 둘지) · 펼친 뒤 다시 접는 동선.
- 폰 390 에서 **매수 탭 한 화면에 얼마나 들어오나** — A(카드 4장) vs B(한 카드) vs C(접힘) vs D(접힌 카드 3장).
- 「○ 선매수 ─ 10만원 ›」(B/C) 처럼 **체크 행에 금액을 얹는 것**이 읽히나, 아니면 A 처럼 「금액」 행을 따로 두는 게 나은가.
- 후매수 상태 칩·「남은 N회」·발동잔량 행 — 상태를 읽을 수 있나(WinForms 는 LED 색 + 「최대」 칸만).
- 태블릿 768(2열)·데스크톱 1280(인라인 편집)에서 매수 열이 매도 열보다 얼마나 길어지나.
- 라벨: 매수 쪽은 인계대로 「주문가격·비교가격」. 매도 쪽 「매도가격·호가잔량」은 현행 그대로 두었다 — WinForms 는 「주문가격·매수잔량」으로 개명했는데 웹도 따를지는 별도 결정.
- 추가매수 최대 0 = 「무제한」 표기, 최소 0 = 「0주」(= 1주) 표기가 맞나.
