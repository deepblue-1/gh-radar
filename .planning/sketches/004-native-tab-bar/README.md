# Sketch 004: 네이티브 하단 탭바 · 앱 아이콘 시안

## Design Question
Phase 21(D-02) 로 탭바는 iOS Swift · Android Kotlin 네이티브다. 웹 화면(토스 B 테마)이 그 위에 그대로 뜨므로, 네이티브 탭바가 웹 헤더·카드·시트와 **한 화면처럼 읽히는 색·모양·높이**를 고른다. 채택안의 수치(좌우 여백 · 높이 · radius · 배경 알파/블러 · 활성 표현 · 본문 하단 여백)가 네이티브 상수의 정본(D-27a)이 된다. 앱 아이콘·스플래시(D-22) 시안 2개도 같은 파일에서 본다.

아이콘은 SF Symbols 근사 벡터다 — 실제 앱은 iOS SF Symbols / Android Material(D-15) 을 쓴다.

## Variants
- **A: 알약 (weekly-wine 계승)** — 좌우 16 · 높이 70 · radius 32 · `--card` 82% + 블러 18 · 그림자 · 탭바 위 150px 하단 페이드. 활성 = `--primary` 14% 원 하이라이트 + filled 아이콘 + primary 라벨. iPad 는 폭 560 가운데. 본문 하단 여백 136.
- **B: 풀폭 토스식** — 바닥에 붙은 풀폭 56 + 홈 인디케이터 34 · `--bg` + 상단 hairline `--line` · 블러·페이드 없음. 활성 = `--fg` filled, 비활성 = `--faint-fg`. 토스증권 앱 탭바 구조. 본문 하단 여백 112.
- **C: 컴팩트 알약 (절충)** — 좌우 12 · 높이 60 · radius 20 · `--card` 불투명 + hairline · 페이드 없음. 활성 = 상단 3px primary 인디케이터 + filled + primary 라벨. 본문 하단 여백 122.

### 아이콘 시안
- **A: 다크 레이더** — `#17171c` 바탕 · 현 파비콘 동심원+스윕 계승 · 스윕 부채꼴에 `#f04452` 그라데이션.
- **B: 블루 레이더 + 상승선** — 토스 블루 그라데이션 바탕 · 흰 레이더 · 아래 상승 빨강 꺾은선.

## What to Look For
- **웹 헤더와의 짝**: 헤더는 `--bg` 88% + 블러다. A(블러 알약) / B(불투명 풀폭) / C(불투명 알약) 중 어느 것이 위아래로 한 화면처럼 읽히는가.
- **본문 잠식**: A 136 · C 122 · B 112 의 하단 여백 — 트레이딩 카드 격자와 종목상세 마지막 섹션에서 얼마나 가리는가. 홈 인디케이터(34) 위 여백이 답답하지 않은가.
- **비활성 상태(종목상세)**: 5탭 전부 기본색일 때 「탭바가 죽어 보이지」 않는가 — B 는 faint 5개, A/C 는 muted 5개.
- **라이트 모드**: A 의 흰 82% 알약이 흰 바탕 위에서 경계가 서는가(hairline 1px inset 로 보강함). B 는 hairline 하나로 충분한가.
- **시트 열림**: Phase 20 키패드 시트(하단 10px 여백 · radius 28)가 뜰 때 탭바가 사라진 자리가 자연스러운가.
- **iPad**: A/C 알약을 560/520 으로 가운데 모은 것 vs B 풀폭 — 820 폭에서 5탭 간격.
- **아이콘**: 홈화면 4×1 줄에서 다른 앱과 섰을 때 눈에 띄는가, 29px 설정 크기에서도 레이더로 읽히는가. 스플래시 라이트/다크 둘 다 자연스러운가.

## 제약
- 색은 `.planning/sketches/themes/toss-dark.css` · `toss-light.css` 토큰만 쓴다(Phase 20 B 테마와 동일 값). 네이티브는 이 hex 를 상수로 옮긴다.
- 탭바 높이·여백은 iOS pt = Android dp 로 그대로 쓴다. 홈 인디케이터 34 는 safe-area inset 으로 기기마다 다르다(목업은 iPhone 15 기준).

## 결정 (2026-09-25)
- **탭바 A 알약 채택.** 수치가 네이티브 상수의 정본이다(CONTEXT D-27a): 좌우 여백 16 · 높이 70 · radius 32 · 배경 `--card` 82% + 블러 18 · 그림자 `0 2px 16px rgba(0,0,0,.18)` + 1px `--line` inset · 바닥 = **화면 끝에서 20**(= safe-area 바닥 + 14 아래, weekly-wine 과 동일 · 홈 인디케이터 위 7 · 인셋 0 기기는 14) · 탭바 위 120 하단 페이드(`--bg` 92% 까지) · 활성 = `--primary` 14% 원 46 + filled 아이콘 + primary 라벨 10px · 비활성 = `--muted-fg` · iPad 는 폭 560 가운데 · 웹 본문 하단 여백 108(폰·iPad 공통 = 70 + 20 + 18).
- **앱 아이콘 A 다크 레이더 채택.** `#17171c` 바탕 · 흰 동심원(r 312/176, stroke 42) + 스윕(512,512→790,352) + 중심 46 · 스윕 부채꼴 `#f04452` 0→55% 그라데이션. 스플래시 = 라이트 `#ffffff` / 다크 `#17171c` 바탕 + 아이콘 96 + 「GH Trade」 워드마크(800). 원본 SVG 는 index.html `#app-a` symbol.
- 과정: 1차 open 에서 폰 프레임이 창보다 커 탭바가 화면 밖에 있었음 → 프레임을 창 높이에 맞춰 축소 + 변형 전환 시 탭바 펄스 테두리 추가 후 재검토.
- **2026-09-25 보정(사용자 지적 「아래 여백이 너무 많다」):** 1차 목업은 바닥 여백을 safe-area 34 + 14 = 48 로 그렸다. weekly-wine 의 제약 `bottomAnchor = safeArea.bottom + 14` 는 부호가 반대(안전영역 **아래로** 14 → 화면 끝에서 20)라 잘못 옮긴 것. 20 으로 고치고 본문 여백 136 → 108, 페이드 150 → 120.
