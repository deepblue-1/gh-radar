## Flagged assumptions (숨기지 않음)

- **21 n 프레임 귀속(구 서버 호환):** 첫 프레임에서 「아직 모름」 슬롯을 미등록으로 채우는 규칙은 새 서버에서 뒤이은 프레임이 곧 덮는다 — 그 사이 웹에 미등록 → 등록이 수 ms 안에 연달아 갈 수 있다(화면 깜빡임 수준 · 데이터 손실 없음). 대안(21 답 끝을 기다렸다 한꺼번에)은 「답 끝」 신호가 와이어에 없어 시한이 필요하다 — 채택하지 않는다.
- **선언 밖 슬롯(초집합):** 인박스 「선언 밖 등록 슬롯을 덧붙인다」 — relay 는 소유 뷰 밖 계좌 프레임을 버린다(RESEARCH Open Q5). 소유 뷰 안이지만 선언 밖(복원본)인 슬롯은 캐시한다.
- **호환 병합의 「충돌」 로그:** 서버 간 1건 가드가 사라지면 같은 거래소 가동 VI 가 여럿인 것이 정상이다 — 구 `vi` 병합의 충돌 warn 은 debug 로 낮춘다.
- **결정이 권고안이 아닐 때:** Task 2 · 3 의 hub 슬롯 캐시 · 원천 해제 · 가드 제거는 같다. 바뀌는 것은 브라우저 프레임 모양뿐이다 — `vi-with-account` 면 새 `t` 대신 구 `vi` 에 `a` 를 싣고(구 webapp 덮어쓰기 위험을 SUMMARY 에 기록), `slot-only` 면 호환 병합 송출을 넣지 않는다. 32-12 · 32-13 은 권고안 `slot-plus-compat` 을 전제로 쓰였다 — 다른 안이면 32-13 Flagged assumptions 의 안별 차이대로 32-13 acceptance 를 고친 뒤 실행한다.
- **예산 경고 · 분할 안 함(플랜 체커):** 추정 150k 는 smart-zone 100k 를 넘는다. 관련 파일의 절반 가까이가 테스트 · 헬퍼(envelope · hub · fanout 테스트 4개 · frames · fake-gateway)이고, 슬롯 캐시 · 원천 · 가드 · replay 가 같은 hub 자료구조를 고치므로 나누면 중간 상태에서 relay 테스트가 깨진 채 플랜 경계를 넘는다. 태스크마다 verify → 경로 지정 커밋 뒤 다음 태스크 read_first 만 새로 읽는다.
