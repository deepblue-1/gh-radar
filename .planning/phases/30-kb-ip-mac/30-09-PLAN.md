## Drift check (planner 확인 · 2026-10-11 — 코드 변경 근거 없음)

- relay `dispatcher.reconcileUser` 는 Admin 라우트(계좌 PUT · 생성 · 다시 반영)에서 **요청한 DMA 사용자 하나**만 계획한다. 87 수신이 reconcile 을 부르는 경로는 없다(`grep -rn reconcileUser relay/src` = admin-api 라우트뿐).
- `planServerOps` 는 그 사용자 · 그 서버 의도 행만 diff 한다. 다른 사용자 87 값은 R3-02 되싣기(`otherByNo`)에 읽기만 한다 — 전파 뒤에는 공유 계좌 사용자들이 같은 값이라 되싣는 값도 같다.
- DB 의도에는 IP/MAC 이 없다 → shared `sameValues` 는 의도에 IP/MAC 이 없으면 비교하지 않는다(GC-02) → 전파된 값은 `changed` 가 아니다. 개요 파생 `indexRaw` 의 `fieldsOf` 는 87 IP/MAC 을 칩 판정에서 뺀다. `snapshot-sink` 의 DB 적재(`p_users`)와 `session-sync` 의 계좌 선언은 IP/MAC 을 싣지 않는다.
- op 3 ok + rev 변경 뒤 relay 는 87 을 기다려(`ADMIN_SNAPSHOT_WAIT_MS`) 캐시를 갈아 끼운 뒤 응답한다 → PUT 응답 뒤 `onChanged` 재조회의 `GET /users`(relay `/internal/admin/order-endpoints` = 87 캐시)에 함께 쓰는 사용자의 새 값이 실린다.
- 결론: relay · server 변경 불필요. Task 2 가 shared 단위 테스트로 drift 없음을 고정한다.
