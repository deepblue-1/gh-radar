**단계 규칙(RESEARCH Pattern 3 확정판):**
R1 체인 루트 — 행에서 시작해 `order_type IN ('M','C')` 인 동안 같은 (gateway, trade_date, account_no) 의 `order_no = org_order_no` 행으로 거슬러 오른다(깊이 상한 20). 루트 = 가장 위 행. 부모가 없으면(전일 원주문) 마지막 `org_order_no` 문자열이 키 · 루트 행 없음. 체인 키 = 루트 `order_no` · 로컬 거부(order_no NULL) = `'R:'||journal_epoch||':'||reject_seq`.
R2 구성원 = 루트 + 루트에서 `order_type = 'M'` 로 내려가는 행(재귀 · status ≠ 'rejected'). C 행은 구성원이 아니라 취소 사건. Σfilled = 구성원 `filled_qty` 합. 살아 있는 구성원 = status IN ('accepted','partially_filled').
R3 rank — accepted 1 · first_fill 2 · filled / rejected / cancelled / suppressed / stale 3 · autosell_start / autosell_done 3(사건마다 체인 키가 다르다).
R4 거부 — 루트 `order_type = 'N'` ∧ status 'rejected' → `rejected`(message = 루트 message).
R5 전량 — 루트 qty 가 있으면 Σfilled ≥ 루트 qty, 루트 행이 없거나 qty NULL 이면 구성원 전부 status 'filled' → `filled`(avgFillPrice = 체인 구성원 주문번호의 E 행 Σ(exec_qty×exec_price)/Σexec_qty 반올림 · 시각 = 마지막 E gw_time).
R6 취소 — 살아 있는 구성원 0 ∧ Σfilled < 루트 qty ∧ 취소된 구성원이 있다. 수동 판정 = 그 체인의 C 행 중 `requester = 'Manual'` 이 있거나 취소된 구성원 주문번호의 kind 7 `cancel_reason = 1` → `suppressed`. 아니면 `cancelled`(cancelReason = 최신 kind 7 cancel_reason · 거래소 자기 취소(C 행 없이 구성원 자기 status cancelled)이고 kind 7 이 없으면 5 「거래소 취소」 · cancelledQty = 루트 qty − Σfilled · price = 마지막 살아 있던 구성원 price · 시각 = 취소 행 updated_at).
R7 첫 체결 — Σfilled > 0 ∧ R4~R6 아님 → `first_fill`(filledQty = Σfilled · lastFillPrice = 마지막 E exec_price · 시각 = 마지막 E gw_time).
R8 접수 — 트리거가 루트 N 이고 status ≥ accepted · R4~R7 아님 → `accepted`(시각 = 루트 created_at). 정정 행 accepted 는 접수를 만들지 않는다(D-10).
R9 자동매도 억제 — 루트 구분 group = 9 → 단계가 무엇이든 `suppressed`(D-22).
R10 자동매도 사건 — kind 11 → `autosell_start`(basis = queue_case · basePrice = bid1_price · triggerPrice = price · soldQty 0) · kind 13 ∧ cond_actual = 4 ∧ cond_threshold ≠ 4 → `autosell_done`(soldQty = qty · avgSellPrice / pnlPct = 같은 계좌 · isin · 거래일의 그 kind 13 직전 kind 11 gw_time 이후 매도 E 행). 그 밖 전략 행은 무시.
R11 당일 — `trade_date <> (now() AT TIME ZONE 'Asia/Seoul')::date` → `stale`.
R12 구분 짝 — 루트 order_no 로 kind IN (3,6) 최신 1행 `"group"`(색인 `idx_dma_strategy_events_order`). 로컬 거부는 같은 계좌 · isin · result_code 의 kind 8 중 루트 created_at 과 3초 안 최신(RESEARCH A5). 못 찾았고 origin 이 manual/vi 가 아니면(limit_chaser · NULL — A6) `p_allow_fallback = false` 일 때 deferred. 취소(R6)의 kind 7 이 없고 C 행 requester 가 'Manual' 이 아니며 거래소 자기 취소도 아니면 같은 deferred 규칙.
