RLS·REVOKE 문단은 건드리지 않는다(컬럼 추가는 기존 정책을 바꾸지 않는다).

`packages/shared/src/relay.ts`: `OrderType` 을 `"N" | "M" | "C"` 로 넓히고 「정정("M")은 v1 범위 밖 (D-21)」 주석을 「Phase 18 D-21 에서 열림」으로 갱신한다. `RelayOrderCancelMsg` 바로 아래에 `RelayOrderModifyMsg` 를 신설한다 — 필드 순서는 `t · rid · isin · exchange · orgOrderNo · side · qty · price · accountNo`, 타입 위 블록 주석에 와이어 근거와 「거래소는 원주문을 승계한다」·「예약(Q-ID)/시간외종가(G2/G3) 원주문은 서버가 정정을 거부한다 — UI 가 잠그고 relay 는 판정하지 않는다」를 적는다. `RelayInbound` 유니온에 새 멤버를 추가한다(zod 쪽과 쌍이다).

`relay/src/ws/protocol.ts`: `RelayOrderCancelSchema` 와 같은 모양으로 `RelayOrderModifySchema` 를 만들고 — `t: z.literal("order.modify")`, 공용 브랜드 스키마 재사용, `orgOrderNo: z.string().min(1)`, `side` 는 기존 주문 side 스키마 재사용 — `RelayInboundSchema` 의 `discriminatedUnion` 배열에 넣는다.

`relay/src/dma/envelope.ts`: `toWireOrderType` 에 `"M"` 분기를 더하고 「스키마는 "M" 을 알지만 relay 는 만들지 않는다」 주석을 갱신한다. `buildDirectOrderReq` 의 원주문번호 가드 조건을 취소 단독에서 취소·정정 양쪽으로 넓히고, 에러 메시지는 주문 종류에 맞는 한국어 두 갈래(`정정 주문에는 원주문번호가 필요합니다` / 기존 취소 문구)로 나눈다. `OrderBuildError(code, 한국어 메시지)` 쌍과 「위치 인자 `createDirectOrderReq` 를 쓰지 않는다」 규율은 유지한다.

`relay/src/ws/order-handler.ts`: `dupKey` 와 `handle` 의 2분기(`const isCancel = msg.t === "order.cancel"`)를 3분기로 바꾼다 — `kind: OrderType` 을 `"C" | "M" | "N"` 으로 계산하고, `needsOrg = kind === "C" || kind === "M"`, `side` 는 취소만 `"S"` 로 적고 정정·신규는 요청 값을 쓴다(취소가 `"S"` 인 이유는 원주문 방향을 모르기 때문이고 정정은 안다 — 이 근거를 주석에 남긴다). `insert` 와 조립 두 곳이 같은 `orderType`/`orgOrderNo` 표현을 쓰므로 **둘 다** 고친다. `dupKey` 의 docstring 에 정정 규칙(`M|orgOrderNo|price|qty`)과 그 근거(같은 원주문을 서로 다른 가격으로 연달아 정정하는 것이 상따 화면의 정상 조작이다)를 세 번째 불릿으로 적는다. 게이트 ② `session.allowedAccounts` 대조는 **3분기 전부**가 통과해야 한다 — 정정용 우회 분기를 만들지 않는다. 어느 이탈 경로에서도 `release(state, keys)` → `reject(conn, rid, 한국어 사유)` → `return` 3종 세트를 유지한다.

`relay/src/store/orders.ts`: `OrderInsertRow` 에 `pieceCount?: number` · `krxSession?: "G2" | "G3"` 을 더하고 `supabaseOrderInsertSink` 의 컬럼 매핑에 `piece_count: row.pieceCount ?? null` · `krx_session: row.krxSession ?? null` 을 더한다(이 태스크에서는 값이 항상 `undefined` 로 들어오지만 컬럼 매핑을 여기서 닫는다 — Task 2 가 값을 채운다).

`webapp/src/lib/relay-provider.tsx`: `RelayOrderRequest.kind` 를 `"new" | "modify" | "cancel"` 로 넓히고 `buildOrderFrame` 에 cancel 분기와 같은 모양의 modify 분기를 더한다 — `orgOrderNo` 가 비면 「정정할 원주문번호를 확인하지 못했어요.」, `side` 가 없으면 기존 「매수·매도 구분을 확인하지 못했어요.」. throw 하지 않는 `{ok}` 결과형과 존댓말 사유, `sendOrder` 의 「어떤 경로에서도 reject 하지 않는다」·`newRid` 유일성 규율은 그대로 둔다.
