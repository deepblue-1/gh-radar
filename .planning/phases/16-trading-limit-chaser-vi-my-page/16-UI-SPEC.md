## Spacing Scale

기존 4-point 토큰 스케일 상속 (globals.css `--s-*`). **신규 값 없음.**

| Token | Value | Usage (Phase 16) |
|-------|-------|------------------|
| `--s-1` | 4px | 배지 내부 갭, 도트·라벨 갭, 파생값 행 갭 |
| `--s-2` | 8px | 폼 행 간격, 필드 라벨↔입력 갭, 배지 묶음 갭 |
| `--s-3` | 12px | 카드 내부 패딩, 표 셀 좌우(`--cell-pad-x`), 사이드바 좌우 패딩 |
| `--s-4` | 16px | 데스크톱 2축 그리드 gap, 액션 바 좌우 패딩 |
| `--s-5` | 24px | 데스크톱 main 좌우 패딩, 게이트 박스 좌우 패딩 |
| `--s-6` | 32px | 게이트 박스 상하 패딩 |
| `--s-8` / `--s-10` | 48 / 64px | 페이지 레벨 여백(기존 상속) |

카드 사이 세로 간격(상태줄↔카드 포함)은 **`--s-2`(8px)** 를 쓴다. 근거: 상따 한 화면에 카드가 9개(전략 6박스 + 상단 + 호가 + 로그) 쌓여 `--s-3`(12px) 은 세로 스크롤을 한 화면 더 만든다. 전략 6박스 2열 그리드의 열 간격도 같은 `--s-2`(8px) 이며, 계좌 카드 내부 2열 그리드만 `--s-3`(12px) 을 쓴다(§Component Inventory C 레이아웃 산술). **스케일 예외 없음 — 본 phase 의 모든 레이아웃 갭·패딩은 4의 배수다.**

**Radius:** `--r-sm`(4, 배지·소형 버튼) · `--r`(6, 사이드바 항목·세그먼트) · `--r-md`(8, 입력·표 래퍼·액션 바) · `--r-lg`(12, 카드·다이얼로그).

**행 높이 — 밀도 계약:**

| 표면 | density scope | `--row-h` | 근거 |
|------|---------------|-----------|------|
| 상따 호가 5단 | `data-density="compact"` | **32px** | Phase 15 사다리와 같은 baseline. `compact` 명시로 모바일에서도 32px 유지 |
| 미체결 / 잔고 / VI 주문내역(데스크톱 표) | `data-density="default"` | 36px (모바일 자동 44px) | 취소 버튼·확인 체크 터치 여유 |
| 사이드바 항목 | — | 1단 36px / 2단 32px / 3단(전략) 30px | 트리 깊이에 따라 시각 위계 |
| My page 전략 행 | — | **최소 44px** | 모바일 터치 타깃(링크 + 배지) |

**컴포넌트 고유 치수** (스페이싱 토큰이 아니라 컴포넌트 자체 크기 — 전부 근거 있음. 이 값들 사이의 **갭·패딩은 위 4-point 스케일을 따른다**):

- **스위치 44×26px** — `ui/switch.tsx` 기본보다 크게 키운다. D-05 가 확인 다이얼로그를 없앴으므로 **오터치 방지를 크기·간격으로만** 해야 한다. 좌우 인접 요소와 최소 8px 간격.
- **VI 확인 체크 22px**(표 안) — 20px 배지·36px 행에 맞춘 값. 클릭 타깃은 패딩 포함 **44×44** 를 확보한다.
- **미체결 취소 버튼 26px**(모바일 32px) — Phase 15 예외 승계.
- **배지 높이 20px, 폰트 11px / 600** — 사이드바 3단 항목에 배지 2개가 들어간다. **새 타이포 티어를 만들지 않고** §Typography 의 11px 마이크로 예외를 그대로 쓴다. 공간이 모자라면 **좌우 패딩을 6px → 5px 로 줄이되 사이즈·웨이트는 건드리지 않는다.**
- **하단 액션 바 높이 56px**(모바일 2행 시 96px) — 40px 버튼 + 상하 `--s-2`(8px).
- 컴포넌트 내부 패딩(배지/버튼/다이얼로그 세부)은 Phase 3 에서 락된 컴포넌트 값을 따른다.

## Typography

기존 타입 토큰 상속 (globals.css `--t-*`). **4 사이즈(20 / 16 / 14 / 12) + 11px 마이크로 예외 1개 · 2 웨이트(400 / 600).** Phase 16 은 새 사이즈 티어도 새 웨이트도 도입하지 않는다.

| Role | Size | Weight | Line Height | 적용 |
|------|------|--------|-------------|------|
| 페이지 제목 | 20px (`--t-h3`) | 600 | 1.2 (`--lh-tight`) | 「새 상따 전략」 / 「VI 변동성완화 종합주문」 / 「My page」 |
| 본문 · 입력값 · 버튼 · 박스 제목 | 14px (`--t-sm`) | 400 / 600 | 1.5 | 전략 박스 제목, 폼 입력값(**`.mono`**), 사이드바 1·2단, 액션 바 제목, 게이트 본문 |
| 라벨 · 표 셀 · 상태줄 · 힌트 | 12px (`--t-caption`) | 400 / 600 | 1.5 | 필드 라벨, 표 헤더·셀(**숫자는 `.mono`**), 상태줄, 파생값 행, 빈 상태 보조문 |
| 게이트 제목 | 16px (`--t-base`) | 600 | 1.5 | 「DMA 계정이 연결되지 않았어요」 등 |

**Weights: regular 400 + semibold 600 2단만 사용한다. 700 을 새로 적용하는 표면은 없다.**

- **마이크로 배지(전략 상태 배지 6종 · 거래소 태그 KRX/NXT · VI 주문 상태 배지)** — **11px / 600.** 아래 11px 마이크로 예외 티어를 그대로 쓴다. 10px/700 티어는 만들지 않는다. 사이드바 3단에서 폭이 모자라면 **좌우 패딩(6 → 5px)만 줄인다** — 사이즈·웨이트는 유지한다.
- **사이드바 그룹 헤더(「종목검색」·「트레이딩」)** — **11px / 600 / `--muted-fg`.** 클릭 불가 소제목이지만 항목(14px / 400, 활성 600, `--fg`)과는 **사이즈 + 색**으로 이미 구분된다. 웨이트를 700 으로 올리지 않는다.
- **상속만, 신규 도입 없음** — 헤더 로고 700(Phase 4 기존) · 버튼 `font-medium 500`(Phase 3 lock). 기존 컴포넌트에서 수동적으로 상속될 뿐, Phase 16 이 새로 적용하는 요소는 없다.

**마이크로 사이즈 예외 (11px) — 4-사이즈 스케일 밖 단일 예외, Phase 15 선례 승계:** 사이드바 그룹 헤더, 사이드바 3단(전략 목록) 항목, 배지 3종(전략 상태 · 거래소 · VI 주문 상태), 전략 로그, 호가 사다리 상한가/하한가 마크, 표 셀 보조 캡션(주문번호·「상따」 출처 태그), 액션 바 보조문, 파생값 단위. 웨이트는 이 예외 안에서도 400 / 600 만 쓴다.

**숫자 규칙 (전 표면 강제):**

- 모든 가격·수량·금액·비율·시각·**계좌번호**·**전략키(ISIN)** 는 **`.mono`**(Geist Mono, `tabular-nums slashed-zero`). 표·입력 안에서는 **우측 정렬(`.num`)**, 라벨 옆 인라인일 때는 좌측.
- 방향색이 필요한 숫자(평가손익·수익률·등락)는 반드시 `ui/number.tsx` `withColor` 를 통과시킨다. **방향색이 필요 없는 숫자(잔량·수량·주문가·금액·상승률 설정값)에는 `withColor` 를 쓰지 않는다.**
- `%` 스케일 함정: 서버 정수 %(22.0 = 22%) ↔ `<Number format="percent">` 소수 기대 → `/100` 변환(`stock-hero.tsx` 선례).
- 파생 숫자(산출 주문수량 / 실제 주문금액 / 예상 매도수량)는 입력이 아니라 **읽기 전용 행**으로 표시하고 라벨에 「산출」·「예상」을 붙인다. **서버 계산값이 정본**임을 §Copywriting 에 고지한다.
- 한글 혼용: `html[lang="ko"]` 전역 규칙(`word-break:keep-all`, `letter-spacing:-0.01em`) 상속.

### 신규 토큰 0개 — `--warn` 결정 (D-24(b) 해석)

**`--warn` / `--warn-bg` 는 `webapp/src/styles/globals.css` 에 존재하지 않는다**(실측 2026-09-08, 전 저장소 grep). 초안 목업의 자기 주석도 「채택 시 globals.css 에 토큰 추가 필요」라고 적고 있었다. D-24(b) 의 구속 조항은 **「globals.css 신규 토큰 없음」** 이므로, 채택안은 **주황을 쓰지 않는다.**

| 초안에서 `--warn` 이던 곳 | 채택안 |
|---------------------------|--------|
| 자동취소 박스 테두리·제목 | **중립** — 테두리 `--border` 1.5px, 제목 `--fg`, 헤더에 「가드」 캡션 |
| 「매도대기」 배지 · 대기 LED | **중립** — `--muted` 배경 / `--muted-fg` 텍스트 + **속 빈 도트**(채운 도트와 형태로 구분) |
| VI 110/119초 데드라인 진행바·카운트다운 | **2단계** — 여유(≥20초) `--muted-fg`, 임박(&lt;20초) `--destructive` |
| 매핑 없음 게이트 박스 | **중립** — `--muted` 배경 + `--border`(Phase 15 C13 권한 없음 게이트와 동일 톤) |

결과적으로 색 축은 **매수 빨강 / 매도 파랑 2개**로 유지되고, 「가드·대기·중지」는 색이 아니라 **중립 + 형태**로 읽힌다. 3색 축(빨강/파랑/주황)을 만들면 60/30/10 의 10% 예산이 초과되고, 고밀도 전략 화면에서 빨강↔주황이 주변시로 구분되지 않는다.

> **참고 변형:** 두 목업 툴바의 「주황(--warn 추가 시)」 버튼을 누르면 `--warn` 2종을 추가했을 때의 모습을 즉시 비교할 수 있다. 그 안을 채택하려면 globals.css 에 light/dark 각각 `--warn`·`--warn-bg` **4값**을 추가해야 하며 이는 Phase 3 토큰 락 변경이다. → §열린 질문 FLAG-1.

### `--up` / `--down` **금지** 목록

- **연결 상태(DMA Ready/재접속/실패) 배지·문구** — Phase 15 규칙 승계. `--muted`/`--muted-fg`/`--fg`/`--destructive` 만.
- **거래소 태그 KRX/NXT** — 방향 의미가 없다. 둘 다 중립이며 **KRX = 테두리형 / NXT = 채운 `--muted`** 로 형태 구분.
- **「매도대기」·「중지」·「접수 전」·「취소」 배지** — 중립.
- **잔량·수량 숫자 자체** — 바(배경)만 틴트.
- **취소·삭제·비활성화 버튼** — 아래 토큰 충돌 항목.
- **로딩·스켈레톤·빈 상태·게이트 안내** — 전부 중립.

### 토큰 충돌 경보 (Phase 15 실측 승계)

| 충돌 | 값 | 대응 |
|------|-----|------|
| `--destructive` == `--up` | light/dark 모두 동일 oklch | **채움 빨강 버튼을 파괴적 액션에 쓰면 매수 버튼과 구분되지 않는다.** 「전체 비활성화」·「중지」·「전체 취소」·「✕ 취소」는 전부 **테두리 + `--destructive` 텍스트 + 투명 배경**. 채움 빨강은 **매수 계열 전용** |
| `--primary` == `--down` | light/dark 모두 동일 oklch | **전략 6박스 내부와 VI runbar 에 `--primary` 를 쓰지 않는다**(매도 파랑 오독). 예외는 아래 accent 5곳뿐 |

### Accent (`--primary`/`--accent`/`--ring`) reserved for

1. **사이드바 활성 항목** — `--accent` 배경 + `--accent-fg` 텍스트 (기존 `app-sidebar.tsx` 규칙 그대로)
2. **토글/세그먼트 활성 상태** — 거래소 KRX/NXT, 감시 대상, 미체결 필터
3. **더티(미반영) 표시** — 필드 라벨 `--primary` + 입력 테두리 `--primary` + 하단 액션 바 상단선 `--primary` + **「수정」 버튼 `--primary` 채움**
4. **체크박스 checked 상태** — `--primary` 채움 (VI 확인 체크 포함)
5. **입력 포커스 링** — globals.css 전역 double-ring(`--ring`) 상속

그 외 인터랙티브 요소(행 hover, 링크, 더보기)는 `--border` + `--muted` hover 로 처리한다. **accent 남용 금지.**

**「수정」 버튼이 accent 를 쓰는 이유:** 이 화면에서 파랑은 「내가 바꿨고 아직 서버에 안 갔다」는 **단일 의미**로만 등장한다. 매수(빨강)·매도(파랑 `--down`)와 혼동될 위험은 위치로 차단한다 — 더티 표시는 **폼 안이 아니라 화면 하단 고정 바**에만 색면으로 나타난다.

### 국내 색상 관례 (Phase 15 승계)

상승·매수 = **빨강 `--up`**, 하락·매도 = **파랑 `--down`**. 전 표면에서 반전 금지.

## Interaction Contract

### 조작 규율 — 스위치는 즉시, 값은 「수정」 버튼 (핵심)

1. **스위치(매수주문·매도주문·한방체결)는 확인 없이 즉시 전송**(D-05). 처음 켜는 스위치가 등록(`crud "C"`), 마지막 켜진 스위치를 끄면 삭제(`crud "D"`). 오터치 방지는 **44×26 크기 + 최소 8px 간격 + 박스 헤더 우측 고정 위치**로만 한다.
2. **값 변경은 즉시 전송하지 않는다**(D-06 — 초안의 「0.3초 자동 반영」 폐기). 필드 값이 서버값과 달라지면 그 필드가 **더티**가 되고:
   - 라벨이 `--primary` + `● ` 접두, 입력 테두리 `--primary` + 2px 링
   - 화면 하단에 **액션 바**가 나타난다(더티 0 → 렌더 자체가 사라진다)
   - 「수정」을 눌러야 `SetLimitChaser crud="C"` **전체 29필드를 현재 표시값으로** 전송
3. **스위치 조작은 더티 값을 함께 밀어낸다.** 액션 바 보조문이 이 사실을 상시 고지한다(`스위치를 켜면 변경한 값까지 함께 반영돼요`). 스위치를 막지 않는다 — 상한가 직전 조작을 한 번에 끝내야 한다.
4. **VI 도 같은 규칙**(D-07). 계좌·금액·상승률 = 더티 → 「수정」(`run` 현재값 유지). **시작/중지만 확인 다이얼로그.** 중지 상태에서 「시작」은 현재 폼 값으로 `run=true` 전송.
5. **`ConfirmVIOrderReq(33)` 확인 체크는 즉시 전송**(D-10) — 더티 대상이 아니다. `confirm_locked` 행은 체크 비활성.
6. **삭제 버튼 없음**(D-08). 「전략 삭제」 버튼을 만들지 않는다. 두 스위치가 모두 OFF 가 되면 폼이 빈 상태로 돌아가고 사이드바 목록에서 사라진다.
7. **이탈 경고:** 더티가 있는 채로 라우트 이동·새로고침 시 확인. 라우터 가드 + `beforeunload` 둘 다.

### 서버값 우선 동기화 (D-11 ~ D-14)

- 에코(`SetLimitChaserResp 60` / `SetVITriggerResp 61` / `VIOrderListPush 73`)가 도착하면 **서버값이 항상 이긴다.** 더티 필드도 덮어쓰고, 액션 바는 사라지며, 상태줄에 6초 배너 + 로그 1줄.
- **편집 중 보호·보류 없음.** 값이 바뀌는 순간을 사용자가 놓치지 않도록 배너는 `role="status"`, 덮어쓴 필드 개수를 문구에 넣는다.
- 전략 스냅샷은 **wss 인증 직후 자동 수신**(D-12). 페이지가 따로 요청하지 않는다 → **새로고침 버튼을 만들지 않는다**(D-13).
- 웹/WinForms 출처를 구분하지 않는다(D-14). 세션의 전략 전부를 표시·편집한다.

### 사이드바 · 라우팅

- 그룹 소제목은 **클릭 불가**. 접기 토글·상태 저장 없음(D-16).
- 전략 목록 클릭 → `/trading/limit-chaser/{ISIN}:{accountNo}:{exchange}`. **키에 `:` 가 들어가므로 `encodeURIComponent` 로 세그먼트를 인코딩**하고 표시 시 디코드한다.
- 「상따」 항목 자체 → `/trading/limit-chaser/new`(빈 폼). 목록 항목과 활성 표시가 겹치지 않게, `new` 일 때만 「상따」에 `aria-current`.
- 매핑 판정 원천은 **전역 wss 상태 프레임**(D-19/D-22). 판정 전(연결 중)에는 트레이딩·My page 를 **숨긴 상태로 시작**하고, `ready` 수신 후 나타난다 — 나타났다 사라지는 깜빡임을 피하기 위해 반대로 하지 않는다.
- 모바일 drawer 는 링크 클릭 시 자동 닫힘(`data-nav-item` 유지). **그룹 소제목 클릭은 닫히지 않는다**(링크가 아니므로).

### 오조작 방지 (되돌릴 수 없는 액션)

1. **파괴적 액션은 전부 테두리형** — `--destructive` == `--up` 충돌 때문에 채움 빨강은 매수 전용.
2. **다이얼로그 기본 포커스는 항상 「취소 / 닫기」.** Enter 연타로 실행되지 않는다.
3. **제출 후 즉시 재활성 금지** — 응답(또는 5초 타임아웃) 전까지 버튼 비활성 + `반영 중…`.
4. **「전체 비활성화」는 My page 에만.** 상따·VI 페이지에는 두지 않는다(D-09) — 편집 중 오클릭 경로를 만들지 않는다.
5. **VI 「시작」 다이얼로그는 금액·상승률을 요약에 반드시 포함**한다. 사람 확인 없이 주문이 나가는 유일한 기능이다.

### 실시간 갱신 · 애니메이션 예산

- 에코·스냅샷 수신 시 **변경된 필드만 배경 플래시 1회 ≤150ms**(`background-color` 만). 레이아웃 shift 0.
- 데드라인 카운트다운은 **1초 간격 텍스트 교체 + 진행바 폭 즉시 반영**(transition 없음). 20초 경계에서 색이 한 번 바뀐다.
- 액션 바 등장은 **fade 120ms** 만. slide-up 금지(하단 콘텐츠를 가리는 순간에 시선이 튄다).
- 호가 5단은 Phase 15 규칙 승계(100ms 코얼레싱, 브라우저 추가 코얼레싱 없음, 플래시 큐잉 금지).
- `prefers-reduced-motion: reduce` → 플래시·점멸 도트·shimmer·fade 전부 비활성, 값만 교체.

### 키보드 접근성

- 탭 순서(상따): 사이드바 → 종목 → 거래소 토글 → 계좌 → 매수 스위치 → 매수 필드… → 자동취소 → **하단 액션 바(더티일 때)** → 호가 5단(1 stop, roving) → 계좌 탭 → 취소 버튼들.
- **더티 액션 바가 나타나면 포커스를 빼앗지 않는다.** `aria-live` 로만 알린다.
- 호가 5단은 Phase 15 와 동일한 roving tabindex(↑/↓ 이동, Enter/Space 로 비교가격 채움).
- VI 주문내역 표의 확인 체크는 행 순서대로 tab. `confirm_locked` 는 tab 순서에서 제외(`disabled`).
- 다이얼로그는 Radix 포커스 트랩·ESC·복귀 포커스 상속. 기본 포커스만 취소 버튼으로 override.

### 반응형

**모바일 390px 이 기준이다.**

| 폭 | 배치 |
|----|------|
| **<1024px** | 사이드바 = 헤더 ☰ drawer. **전 표면 1열 세로 스택** |
| **1024 ~ 1279px** | 사이드바 고정 240px 출현(기존 AppShell `lg:block`). 본문은 **여전히 1열**(콘텐츠 735px 로는 2축이 잘린다) |
| **≥1280px** | 위 §Component Inventory 의 2축 그리드 적용 (상따 595/380 · VI 420/555 · My page 계좌 476/476) |

**모바일 세로 순서 (확정):**

- **상따**: 종목·거래소·계좌 → 상태줄 → 매수주문 → 매수가격 → 한방체결 → 매도주문 → 매도가격 → 자동취소 → 호가 5단 → 미체결/잔고 → 전략 로그 → *(더티 시 하단 고정 액션 바)*
- **VI**: 상태줄 → 설정 + 시작/중지 → VI 주문내역(카드) → 미체결 → 잔고 → *(더티 시 액션 바)*
- **My page**: 상태줄 → 전략 현황 → 계좌 A(미체결 → 잔고) → 계좌 B(미체결 → 잔고) → …

**모바일 세부:**

- 하단 액션 바는 **화면 하단 고정**(`position: fixed`), 본문 하단에 96px 여백을 준다. 하단 탭바는 도입하지 않는다(D-18).
- VI 주문내역은 표가 아니라 **카드 행**(9열은 390px 에 들어가지 않는다). 확인 체크 · 종목 · 상태 배지 1행, 메타(발동가·상승률·주문가×수량) 1행, 데드라인 1행.
- 미체결·잔고 표는 `--row-h: 44px` + **가로 스크롤 허용**(`.tbl-wrap { overflow-x: auto }`). 열을 숨기지 않는다.
- 전략 6박스는 1열. 각 박스의 라벨 열은 80px 고정, 입력이 나머지를 차지한다(390 − 24 패딩 − 24 박스패딩 − 80 − 8 = **254px**).
- 사이드바 3단 전략 항목은 drawer 안에서도 같은 트리. 종목명 + 배지 2개가 넘치면 종목명만 ellipsis(배지는 줄이지 않는다 — 상태가 정보다).

### 색 비의존 (WCAG 1.4.1)

- 전략 상태는 **배지 텍스트 + 도트 형태(채움/속빔) + 색** 3중.
- 매수/매도는 **박스 제목 텍스트 + 위치(매수 3박스 먼저, 매도 2박스 뒤) + 색**.
- 미체결 매매 구분은 `▲ 매수` / `▼ 매도` 부호 병기.
- 데드라인 임박은 색 + **숫자 감소 + 진행바 길이** 3중.
- 거래소는 색이 아니라 **텍스트(KRX/NXT) + 배지 형태**로만 구분.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | switch, button, dialog, badge, table, card, toggle, toggle-group, tabs, tooltip, skeleton, separator, sheet, popover — **기존 설치본**(`webapp/src/components/ui/`) | not required (already vetted, in-repo) |

| 3rd-party | **none** | not applicable — `components.json.registries = {}` (실측 2026-09-08) |

**`checkbox` 도입 사유:** 상따 폼 6개 + VI 주문내역 행별 확인 체크. `confirm_locked` 비활성 상태, 표 셀 안 라벨 연결, 전역 double-ring 포커스, 그리고 같은 폼의 Radix `Switch` 와의 시각·키보드 일관성이 필요하다. Phase 15 의 `tabs` 신규 설치와 같은 성격의 판단이다.

**여전히 비채택:**

| 후보 | 비채택 사유 | 대체 |
|------|-------------|------|
| `select` | 계좌 2~3개. Phase 15 결정 승계 | 네이티브 `<select>` + 토큰 스타일 + `<label>` |
| `sonner` (토스트) | 새 npm 의존성. Phase 15 D-36 이 알림 채널을 상태 영역 누적으로 이미 고정 | 상태줄 인라인 배너(6초) + 전략 로그 |
| `accordion` / `collapsible` | 사이드바 그룹은 **항상 펼침·접기 없음**(D-16) | 정적 중첩 `ul` |

| `sidebar` (shadcn block) | 기존 `AppShell` + `app-sidebar.tsx` 가 이미 drawer·240px·`data-nav-item` 계약을 갖는다. 블록 도입은 Phase 4 레이아웃 전면 교체 | 기존 컴포넌트 확장 |

## 열린 질문 (FLAG)

**FLAG-1 — `--warn` 주황 토큰: 채택안은 「추가하지 않음」.**

CONTEXT D-24(b) 는 「자동취소 박스 주황은 `--warn` 토큰 **재사용**(globals.css 신규 토큰 없음)」이라고 적었으나, **`--warn` / `--warn-bg` 는 globals.css 에 존재하지 않는다**(실측 2026-09-08). 초안 목업 자신도 「채택 시 globals.css 에 토큰 추가 필요」라고 적고 있었다. 두 지시(재사용 / 신규 토큰 없음)를 동시에 만족시킬 수 없어 **「신규 토큰 없음」을 구속 조항으로 우선**해 §Color 처럼 중립으로 확정했다.

- 채택안(중립)을 그대로 두려면 **추가 조치 없음**.
- 주황을 원하면 globals.css 에 light/dark 각각 `--warn`·`--warn-bg` **4값**을 추가해야 하며, 이는 Phase 3 토큰 락 변경 + `data-variant="warn"` 로 목업에서 미리 확인 가능하다. 그 경우 §Color 표에서 자동취소 박스 / 「대기」 배지 / 데드라인 1단계 3곳을 `--warn` 으로 되돌리고 본 FLAG 를 해소한다.

**이 FLAG 는 planner·executor 를 막지 않는다.** 채택안(중립)이 기본값이며, 사용자가 주황을 택하면 색 3곳만 교체하면 된다.

그 외 열린 질문: **없음.**
