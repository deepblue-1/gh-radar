① `supabaseOrderInsertSink` 에 `23505` 전용 분기를 넣는다. 16-REVIEW §GC-WR-08 의 Fix 스니펫을 참조하되 이 코드베이스의 규약에 맞춘다:
  - `(error as { code?: string }).code === "23505"` 일 때만 특별 취급한다. **다른 코드는 지금과 완전히 동일하게** 로그 + throw 다 — 예외 삼키기를 넓히지 않는다.

  - 수렴에 성공하면 `logger.warn` 을 남긴다 — 문구에 「같은 사용자·같은 날의 같은 주문번호 insert 경주 — 기존 행으로 수렴」과 `origin` 을 싣고 **계좌번호·주문번호 원문은 싣지 않는다**(마스킹 규율). 조용히 수렴하면 이 경로가 얼마나 도는지 영원히 모른다 (S-5).
  - `row.orderNo` 가 `undefined`/`""` 이면 인덱스 대상이 아니므로(부분 인덱스 `WHERE order_no IS NOT NULL`) 재조회하지 않고 기존대로 throw 한다.
  - 재조회도 `null` 이면 기존대로 throw 한다 — 지어내지 않는다.

② `supabaseOrderSink`(update) 의 `order_no` 셀렉터 경로에 같은 코드 해석을 넣는다. update 가 `23505` 로 실패한다는 것은 **그 값이 이미 다른 행에 있다**는 뜻이다. 이때는 재시도해도 영원히 실패하므로:
  - `logger.error` 로 남긴다 — 문구에 「`order_no` 갱신이 UNIQUE 위반 — 같은 주문번호 행이 이미 있다(감사 기록 분기)」와 셀렉터 컬럼·`23505` 를 싣는다.
  - **throw 하지 않고 정상 반환한다.** 근거 주석: 재시도 1회를 태워도 결과가 같고, 드롭 카운터를 올리면 「이유를 아는 실패」가 「이유를 모르는 실패」와 뒤섞인다. 이 한 경로만 예외이며 나머지 에러는 그대로 throw 한다.
  - 이 결정을 `#drain` 의 재시도 규율 주석과 어긋나지 않게 sink 쪽에 적는다.
