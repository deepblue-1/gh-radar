     **이 입력은 어떤 세션 상태에서도 게이트웨이로 나갈 수 없다.** `0000000000` 은 어떤 세션의 `allowedAccounts` 에도 없으므로 게이트 ② 에서 거부되고(insert 이전), 설령 세션이 없으면 게이트 ① 에서 더 먼저 거부된다. `KR0000000000` 도 `SymbolMap` 이 풀지 못해 게이트 ③-1 에서 막힌다. **이 세 겹의 근거를 프로브 파일 상단 주석에 그대로 적는다** — 다음 사람이 「실계좌에 주문이 나가나?」를 다시 묻지 않게.
  4. 같은 `rid` 의 `{t:"order.result"}` 를 최대 15초 기다린다.
     - `status === "rejected"` → `reachable` (relay 주문 핸들러가 살아서 답했다 = 도달성 증명)
     - 응답 없음(타임아웃) → `unreachable`
     - 연결 실패·핸드셰이크 실패 → `unreachable`
  5. 표준출력에 판정 한 단어(`reachable`/`unreachable`/`inconclusive`)만 찍는다 — 기존 규약과 같다.

② INV-9 호출부를 고친다. 라벨을 `INV-9 브라우저 → relay wss 주문 왕복 도달성` 으로 바꾼다(옛 라벨 「Cloud Run → VM ${ORDER_API_PORT} 도달성」은 **측정 대상 자체가 사라졌다** — 16-16 이 server→relay 내부 HTTP 주문 경로를 없앴다). 가드 조건에서 `server_url()` 검사를 빼고 `SMOKE_AUTH_TOKEN` 만 본다. 3갈래 판정 분기는 그대로 유지하되 `unreachable` 문구를 `order.result 미수신` 으로 바꾼다.
