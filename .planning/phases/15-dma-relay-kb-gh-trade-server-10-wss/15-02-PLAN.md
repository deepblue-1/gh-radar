`relay/src/dma/envelope.ts` — 조립부와 파싱부를 한 모듈에 둔다(와이어 지식의 단일 경계).

**조립(build\*)**: `Envelope` 에는 `createEnvelope()` 가 **없으므로** 반드시 `Envelope.startEnvelope(b) → Envelope.addMsgType(b, MSG.X) → Envelope.addXxx(b, off) → Envelope.endEnvelope(b) → b.finish(...)` 순서로 만든다. 필요한 빌더: `buildLoginReq(userId, password, broker)`(MSG.LoginReq=1), `buildLivePing()`(MSG.LivePing=4, `ping_time` = 현재 UTC epoch seconds uint), `buildGetQuoteReq(isin, exchange)`(28), `buildSubscribeQuoteReq(isin, exchange, subscribe: boolean)`(29), `buildGetTradeTapeReq(isin, exchange, count)`(32). 계좌·주문 빌더(3/25/2)는 **이 plan 에서 만들지 않는다** — D-25 게이트 뒤 plan 소관.

**파싱(parse\*)**: 진입점 `tryParseEnvelope(payload: Buffer): ParsedEnvelope | null` 은 **total** 해야 한다 — 어떤 입력에도 throw 하지 않고 `null` 로 수렴한다. 3단 방어:
1. 최소 크기(8B) — codec 에서 이미 걸렀지만 이 함수도 자체 검사한다.
2. `msgType` 이 `INBOUND_MSG_TYPES` 에 없으면 드롭(카운터 + warn).
3. `msg_type` 으로 분기한 뒤 해당 슬롯 접근자가 `null` 이면 드롭. **`Envelope` 은 union 이 아니라 optional 슬롯을 나열한 table** 이므로 슬롯 null 검사가 필수다.

**필드 가드 (가장 중요 — JS 런타임에 Verifier 가 없고 잘린 버퍼가 예외 없이 깨진 값을 반환한다)**:
- `takeCount(n: number, max: number, label: string): number` — 음수는 0, 초과는 max 로 절단하고 **둘 다 `logger.warn` 을 남긴다**(조용한 절단 금지). 상한 상수 정본: `MAX_ORDER_BOOK_DEPTH = 10`, `MAX_ACCOUNT_LIST_COUNT = 256`, `MAX_HOLDING_COUNT = 500`, `MAX_UNFILLED_COUNT = 1000`, `MAX_REMOVED_ORDER_COUNT = 1000`, `MAX_TAPE_ENTRY_COUNT = 200`.
- 형식 가드: `isValidIsin(s)` = `/^[A-Z]{2}[A-Z0-9]{10}$/` 이고 길이 12, `isValidExchange(s)` = `s === "KRX" || s === "NXT"`, `change_sign` 은 길이 1 문자열이어야 하며 아니면 프레임 드롭.
- `toNum(v: bigint, label: string): number` — `v > BigInt(Number.MAX_SAFE_INTEGER)` 이면 `logger.warn` 후 `Number.MAX_SAFE_INTEGER` 로 클램프. **bigint 를 그대로 JSON.stringify 하면 TypeError** 이므로 이 함수가 유일한 변환 경계다(D-34).
- `exchange_time` 은 "HHMMSSuuuuuu" 원문 문자열 그대로 보존(신선도 원천).

**출력**: `parseQuoteState(env, isSnapshot)` → `RelayQuote`, `parseTradeTape(env, isSnapshot)` → `RelayTape`, `parseServerMessage(env)` → shared 의 `msg` 프레임, `parseLoginResp(env)` → `{success, message}`(현행 스키마 — `accounts` 는 **읽지 않는다**, D-25). 전부 shared 계약 타입을 반환한다.
