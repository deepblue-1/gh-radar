Phase 15 — 호가창 섹션 목업

L1 레이아웃 L2 호가표기 L3 잔량바 상태 실시간 시뮬
목업 사용법 — 상단 토글 3개(L1/L2/L3)가 실제로 화면을 바꾼다. ★ 표시가 연구자 권고안이다.
  • L1 · 전체 레이아웃 — A: [호가][체결][주문] 3컬럼 + 잔고/미체결 전폭 하단 / B(권고): 좌 = 호가+체결, 우 = 주문 위·계좌 아래. B는 "시장 관찰(좌)"과 "내 계좌(우)" 2축으로 시선 이동을 줄이고, 주문 → 미체결 취소 동선이 같은 컬럼 안에서 끝난다.
  • L2 · 호가 10단 표기 — A(권고): 국내 HTS 관례. 가격 1열이 매도10→매수10 으로 연속이라 스프레드·물량 벽을 한눈에 읽고, 클릭 타깃(가격 열)이 하나라 오클릭이 적다 / B: 매도·매수 블록 상하 분리(가격|잔량|바). 가격 축이 두 번 끊긴다.
  • L3 · 잔량 바 — A(권고): 단계 최대값 정규화 → 물량 "벽" 위치가 즉시 보인다 / B: 누적 비율 → 아래로 갈수록 항상 길어져 벽이 묻힌다 / C: 바 없음(밀도 최대, 100ms 갱신에서 숫자만으로 벽 찾기는 인지 비용이 큼).
  • 상태 셀렉터로 준비/로그인 중/계좌 확인 중/재접속/회선 단절/세션 거부/권한 없음/스켈레톤을 모두 확인. 각 상태에서 주문 버튼의 문구·비활성이 바뀐다.
  • 좁은 폭은 브라우저 폭을 900px 아래로 줄이면 실제로 반응하고, 아래 §5 에 390px 고정 렌더도 있다.
  • 인터랙션: 호가 가격 클릭 → 주문 가격 입력 반영(탭은 자동 전환하지 않는다) · 거래소 KRX/NXT 토글 · 매수/매도 탭 · 미체결 취소 버튼 · 체결 테이프 스크롤 내리면 자동 스크롤 정지.

실시간 호가·주문 권한이 없어요

실시간 호가와 주문은 증권사 계정이 연결된 사용자만 이용할 수 있어요. 연결이 필요하면 관리자에게 문의해 주세요.

이 종목의 차트·뉴스·종목토론방은 그대로 이용할 수 있어요.

2 · 연결 상태 6종 + 게이트 2종 — 배지 · 문구 · 주문 버튼

라벨 정본은 gh-trade EventArgs.cs SessionState 개념 이식. 연결 상태에는 --up/--down 을 쓰지 않는다 — 사다리의 상승/하락·매수/매도 의미색과 충돌하기 때문.

3 · 확인 다이얼로그 (오조작 방지)

확인은 웹앱 몫(D-20 — relay 는 판단하지 않는다). 기본 포커스는 취소 버튼에 둔다 — Enter 연타로 주문이 나가지 않게. 주문 취소 버튼은 --destructive 가 --up 과 동일 oklch 라서 채움 대신 테두리로 매수 버튼과 구분한다.
