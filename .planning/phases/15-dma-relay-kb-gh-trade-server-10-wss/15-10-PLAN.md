**`packages/shared/src/stock.ts`**: `StockMaster` 에 `isin: string | null;   // KRX 'ISU_CD' 표준코드 12자 — DMA 게이트웨이 키(D-28). 단축코드 산술 유도 금지` 를 추가한다. `/api/stocks/:code` 가 반환하는 상세 타입에도 `isin` 을 노출한다(현행 타입 구조에 맞춰 `Stock` 또는 상세 응답 타입 중 실제 사용처에 추가 — 웹앱 호가창이 `isin` 을 읽어야 한다).

**`workers/master-sync/src/pipeline/map.ts`**: `krxToMasterRow` 에 `isin` 을 추가하되 **12자 정규식 가드**를 건다 — `const isin = r.ISU_CD && /^[A-Z]{2}[A-Z0-9]{10}$/.test(r.ISU_CD.trim()) ? r.ISU_CD.trim() : null;`. ETP 경로는 `ISU_CD` 를 채우지 않으므로 자연히 `null` 이 되고, 혹시 6자가 들어와도 정규식이 막는다. 주석에 Pitfall 13 을 역참조한다.

**`workers/master-sync/src/pipeline/upsert.ts`**: 두 곳을 고친다.
1. **dedupe merge** — 현재 `deduped.set(r.code, r)` 는 last-wins 라 뒤에 오는 ETP 행이 앞의 주식 행을 통째로 덮는다. `isin` 만은 **기존 non-null 값을 보존**하도록 merge 한다: 같은 code 가 이미 있으면 `{...newRow, isin: newRow.isin ?? existing.isin}` 형태로 넣는다. 다른 필드의 last-wins 동작은 **바꾸지 않는다**(기존 동작 회귀 금지).
2. **dbRows 매핑에 `isin: m.isin` 추가.** 단, `isin` 이 `null` 인 행이 기존 DB 값을 지우지 않도록 **isin 이 null 인 행은 upsert 페이로드에서 `isin` 키를 생략**한다(Supabase upsert 는 명시 컬럼만 SET — Phase 09.1 Plan 07 의 partial upsert 선례). 결과적으로 `isin` 이 있는 행과 없는 행을 두 배치로 나누거나, 행마다 조건부 키 포함으로 처리한다. 어느 쪽을 택했는지 주석에 남긴다.

**테스트**: `workers/master-sync/src/pipeline/__tests__/map.test.ts` — ① 정상 12자 `ISU_CD` → isin 저장 ② ETP 행(`ISU_CD` 없음) → isin null ③ 6자 `ISU_CD` → isin null(정규식 가드) ④ 소문자/공백 포함 → trim 후 판정. `__tests__/upsert.test.ts` — ⑤ 같은 code 로 주식(isin 있음) 다음 ETP(isin 없음) → 병합 결과 isin 보존 ⑥ isin null 행의 upsert 페이로드에 `isin` 키 부재 ⑦ 기존 다른 필드의 last-wins 가 유지됨.

**`server/src/routes/stocks.ts`**: `MASTER_COLS` 에 `isin` 을 추가하고, `server/src/mappers/stock.ts` 의 `StockMasterRow` 타입과 `mergeMasterAndQuote` 결과에 `isin` 을 전달한다. `/api/stocks/:code` 응답에 `isin` 이 실리는지 기존 server 테스트에 케이스를 1건 추가한다.
