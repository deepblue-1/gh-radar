# 상따수정 — 주문로그 · 잔량진행률 (기획서 전문 옮김)

원본: 「상따 시스템- 로그_진행률-20260929.pdf」 (Sep 27, 2026 · @MJ, 7쪽). gh-radar 세션이 2026-09-29 사용자에게 받아 텍스트로 옮김. 스크린샷 2장(평소 화면 · 로그 탭 눌렀을 때)은 WinForms 「상따전략」 창이며 텍스트로만 설명한다.

서로 독립된 두 가지를 만듭니다. 1부 주문로그는 시세·주문 이벤트를 로그 탭에 한 줄씩 기록하고, 2부 잔량진행률은 대기 중인 매수 주문이 체결까지 얼마나 남았는지를 미체결 밑에 보여줍니다. 둘을 잇는 건 2부가 계산해 1부 로그에 넘기는 값 3개(체결예상 누적 · 오차 · 남은 거래량)뿐입니다.

## 스크린샷 설명

평소 화면(수동주문 탭): 상따전략 창. 상단 KRX/NXT 라디오 + 종목 콤보(37703857101 (정근형)). 탭 「수동주문 / 정정/취소 / 거래원 / 로그」. ① 로그 탭 — 새 로그가 오면 숫자 표시(예: 로그 ③). 미체결 표(C · 시간 · 매매 · 단가 · 미체결 · 주문량: 09:52:40 매수 12,350 300 300). ② 미체결 밑에 진행률 — 「줄서기매수 · 체결예상까지 12,000주 남음 [막대] 88%」 대기 주문이 체결예상까지 얼마 남았는지 표시. 그 아래 매수주문/매도주문/취소 설정 카드.

로그 탭을 눌렀을 때(수동주문 입력칸은 이때 가려짐): ① 창 분리 — 로그를 별도 창으로 띄움. 필터 「종목 전체 ▾ · 거래소 전체 ▾ · 창 분리 ↗」. ③ 시간순 목록 — 종목·거래소로 거르기. 5줄 정도 보임. ② 진행률은 그대로 보임 — 탭과 상관없이 항상 표시.

## 공통 규칙 (1부·2부 모두)

- 시각은 ms 단위 (예: 09:45:02.880)
- KRX 와 NXT 는 완전히 따로 처리. 호가·체결·누적거래량 모두 각 거래소 기준이고, 두 거래소를 합산한 거래량은 쓰지 않음
- KRX 데이터로 판단한 주문은 KRX 로, NXT 데이터로 판단한 주문은 NXT 로 냄
- 단일가매매 구간(VI 발동 중, 장 시작·마감 동시호가)은 로그·계산 모두 제외
- 화면 갱신이 시세·주문 처리를 늦추면 안 됨. 화면 표시는 시세·주문 처리와 분리

## 1부. 주문로그 (로그 탭)

로그 탭에 시세·주문 이벤트를 한 줄씩 시간순으로 찍고 저장합니다.

### 화면
- 탭 순서: 수동주문 / 정정/취소 / 거래원 / 로그
- 로그 탭이 가려져 있을 때 새 로그가 오면 탭에 숫자 표시
- 한 목록에 시간순으로 쌓고, 종목·거래소(KRX/NXT)로 거를 수 있게
- 창 분리 버튼: 탭 칸이 작아 한 번에 5줄 정도만 보이므로 별도 창으로 띄울 수 있게
- 스크롤: 휠·스크롤바로 지난 로그를 올려볼 수 있게. 올려서 보는 중에는 새 로그가 와도 화면이 밀리지 않고, 맨 아래에 있을 때만 새 로그를 따라 내려감
- 로그는 전부 저장해서 나중에도 볼 수 있게. 프로그램이 비정상 종료돼도 그때까지의 로그는 남아야 함

### 한 줄 형식
- 주문 로그: `[시간][주문번호][구분] 내용`
- 시세 로그: `[시간][이벤트] 내용`
- 구분: 선매수 / 추가매수 / 줄서기매수 / 호가매도 / 체결매도 (용어는 바뀔 수 있음: 추가매수 → 후매수, 줄서기매수 → 반등매수)
- 모든 줄에 거래소 · 종목 · 누적거래량
- 주문 줄의 시간은 전송 시각. 접수까지 걸린 시간은 `접수 +ms` 로 표시

### 찍는 로그 7가지

| 로그 | 언제 | 기록할 것 (거래소·종목·누적 외) |
|---|---|---|
| 상한가노출 | 매도 10호가 안에 상한가가 처음 보일 때 (종목·거래소당 하루 1회) | 상한가 매도잔량 |
| 상한가진입 | 상한가 매도잔량이 0이 될 때 (재진입마다 새 회차) | 상한가 매수잔량 3회(즉시·1초·3초)와 각 시점 누적 |
| 매수 주문 | 선매수·추가매수·줄서기매수를 낼 때 | 조건(설정값/실측값), 근거 틱, 상한가 매수잔량, 가격×수량, 접수 ms |
| 대기 | 매수 주문이 상한가 매수잔량에 대기로 들어갈 때 | 수량, 체결예상 누적 (2부에서 받음) |
| 체결 | 대기 주문이 처음 체결될 때 | 오차 (2부에서 받음) |
| 매도 주문 | 호가매도·체결매도를 낼 때 | 조건(설정값/실측값), 근거 틱, 매수1 가격·잔량, 가격·방식×수량, 접수 ms |
| 취소·거부 | 주문이 취소·거부될 때 | 사유. 대기 주문 취소면 남은 거래량 (2부에서 받음) |

### 세부 규칙
- 상한가노출: 시초가부터 상한가면 "시초 상한가"로 표시
- 상한가진입: 3초가 지나기 전에 상한가를 이탈하면 그 시점까지만 기록. 이탈 자체와 상한가 첫 매도체결은 로그로 찍지 않음
- 근거 틱: 체결이면 체결가·체결량, 호가면 잔량 변화
- 즉시체결: 매수 주문이 남은 매도잔량에 바로 체결되면 "즉시체결"로 표시하고 대기 없음. 일부만 체결되면 나머지만 대기
- 취소·거부 사유: 거부는 거래소·증권사가 준 사유 그대로, 취소는 취소 원인. 주문번호를 못 받은 거부는 주문번호 자리에 "-"
- 남은 거래량 (취소 줄): 대기 중이던 매수를 취소했을 때만 기록. 체결까지 거래량이 얼마나 더 필요했는지 = 체결예상 누적 − 취소 시점 누적. 예: 1,100,000 − 1,088,000 = 12,000주
- 남은 거래량을 남기는 이유: 체결 직전에 뺐는지, 한참 멀었을 때 뺐는지 나중에 보려고. 대기 전에 거부됐거나 이미 체결된 주문은 비워 둠

## 2부. 잔량진행률 (미체결 밑)

대기 중인 매수 주문마다, 체결까지 거래량이 얼마나 남았는지를 미체결 목록 바로 밑에 보여줍니다.

### 화면
- 위치: 미체결 목록 바로 밑. 탭과 상관없이 항상 보임
- 대기 주문마다 한 줄: `줄서기매수 · 체결예상까지 12,000주 남음 [막대] 88%`
- 첫 체결되거나 취소되면 그 줄은 없앰

### 계산
상한가 매수잔량을 상한가에 선 줄로 보면 됩니다. 상한가 매도체결이 나면 줄이 준 만큼 누적거래량이 늘기 때문에, 같은 시점의 누적 + 잔량(= 줄 맨 끝까지 체결되는 누적)은 체결이 나도 변하지 않습니다. 내 주문이 그 줄 뒤에 섰다면, 누적이 이 값에 도달할 때 내 차례가 옵니다.

**체결예상 누적 = 기준 누적 + 내 앞 물량**
- 기준 누적과 내 앞 물량은 반드시 같은 시점 값 (접수 시점 누적을 섞으면 안 됨). 호가 데이터에 누적거래량이 같이 오면 그 값 사용
- 남은 거래량 = 체결예상 누적 − 현재 누적
- 진행률 = (현재 누적 − 기준 누적) ÷ 내 앞 물량
- 예: 기준 누적 1,000,000 + 내 앞 물량 100,000 = 체결예상 1,100,000. 현재 누적 1,088,000 이면 12,000주 남음, 88%

기준을 어느 호가로 잡을지는 주문 시점에 상한가 매수잔량이 있었는지로 나눕니다 (트리거 종류와 무관).

| | 경우 1: 잔량 보고 낸 주문 | 경우 2: 잔량 쌓이기 전에 낸 주문 |
|---|---|---|
| 해당 주문 | 상한가 유지 중에 낸 주문 (주로 추가매수·줄서기매수) | 선매수, 체결 보고 낸 주문 |
| 기준 누적 | 주문 시점 누적 | 내 주문이 반영된 첫 호가 시점 누적 |
| 내 앞 물량 | 주문 시점 상한가 매수잔량 | 그 호가의 상한가 매수잔량 (내 주문 포함) |
| 예 | 1,000,000 + 100,000 = 1,100,000 | 900,000 + 30,000 = 930,000 |
| 뜻 | 첫 체결 예상 지점 (전량 체결 지점 = 체결예상 누적 + 내 주문수량) | 내 주문이 이 잔량 안에 있으므로, 여기 도달하면 무조건 전량 체결 (보수적) |

- 경우 2는 계산 방법이 두 가지이고 결과는 같음 (편한 쪽으로 구현)
- 방법 A (표의 방법, 직관적): 내 주문이 반영된 첫 호가 시점 누적 + 그 호가의 상한가 매수잔량
- 방법 B: 상한가 첫 매도체결 직전 누적 + 첫 매수잔량. 첫 호가 전에 상한가 매도체결이 먼저 나왔으면 그 체결량도 더함. 내 주문이 첫 호가보다 늦게 들어갔으면 B 는 못 쓰고 A 로
- 예: 상한가 첫 매도체결 직전 누적 900,000, 첫 호가 전에 상한가 매도체결 2,000주, 첫 호가 잔량 30,000 → A: 첫 호가 시점 누적 902,000 + 30,000 = 932,000 / B: 900,000 + 30,000 + 2,000 = 932,000

### 1부로 넘기는 값

| 값 | 언제 | 1부 로그 |
|---|---|---|
| 체결예상 누적 | 대기 시작 | 대기 줄 |
| 오차 = 체결예상 누적 − 첫 체결 시점 누적 | 첫 체결 | 체결 줄 |
| 남은 거래량 | 대기 주문 취소 | 취소 줄 |

- 오차 해석: 경우 1은 + 면 내 앞 주문이 취소된 만큼 일찍 체결, − 면 내가 본 호가와 내 주문 도착 사이에 먼저 들어간 물량만큼 늦게 체결. 경우 2는 보수적으로 잡은 값이라 보통 +
