# gh-radar → gh-trade 작업 요청 — 2026-11-12 · 종목별 한투 뉴스·공시 묶음 조회 계약

## 요청 내용

**gh-trade 가 부를 호출:** `GET <server>/api/news/by-stock?codes=005930,0011T0&days=3&limit=3`
— 사용자 결정 「종목당 최근 3건, 최대 3일까지」(gh-trade-42 가 2026-11-11 확인). gh-trade 목업 「어느 안이든 같은 동작」의 「오늘 것만」 문구는 폐기됐다. 선택 종목 상세 목록만 큰 `limit` 으로 따로 부른다.

gh-radar 가 한국투자증권(한투) 뉴스·공시 제목을 서버에서 모으고, 네이버 뉴스와 합쳐 **종목 묶음 조회** 하나로 준다 — 돌파감지 창 · 상따창 표시용. 테마 조회(`GET /api/themes/by-stock` · ThemeLookup)와 같은 서버 · 같은 꼴이다. `<server>` 는 ThemeLookup · FloatSharesClient 가 쓰는 gh-radar 서버 주소 그대로.

### 계약

| 항목 | 값 |
|------|-----|
| 경로 | `GET /api/news/by-stock` |
| 인증 | 없음 |
| `codes` | 쉼표 구분 1 ~ 100개 · 각 `^[0-9A-Z]{6}$`(영문 포함 신규 코드 `0011T0` 허용) · 같은 코드는 한 번만 센다 |
| `days` | 1 ~ 7 · 기본 3 · 범위 밖은 잘라 맞춤(`days=10` → 7) |
| `limit` | 1 ~ 100 · 기본 20 · 범위 밖은 잘라 맞춤(`limit=500` → 100) |
| 위반 | 400 `{"error":{"code":"INVALID_QUERY_PARAM","message":"<path>: <message>"}}` |
| 한도 초과 | 429 `{"error":{"code":"RATE_LIMITED","message":"Too many requests, retry later."}}` — 전용 제한 IP 당 분 600회 |
| 캐시 | 서버 5초 캐시(같은 코드 집합 · days · limit) · `Cache-Control: public, max-age=5` |

**응답 필드:**

- `asOf` — 응답을 만든 시각
- `feedAt` — 수집기 전체 흐름이 마지막으로 성공한 시각(없으면 null)
- `stocks[]` — **요청의 입력 순서 그대로**, 글 없는 코드도 `items: []` 로 빠짐없이
  - `code`
  - `collectedAt` — 그 종목을 종목별로 마지막 수집한 시각(없으면 null)
  - `count` — 합친 뒤 건수(아래 「뜻」 참고)
  - `truncated` — 읽기 상한에 닿았는가
  - `items[]` — 최신순 앞 `limit` 줄
    - `id` — `kis:<일련번호>` 또는 `naver:<uuid>` · 한 번 정해지면 바뀌지 않음
    - `kind` — `news` · `disclosure`
    - `publishedAt` — 작성 시각
    - `title`
    - `source` — 자료원(언론사 · 「코스닥 공시」 등)
    - `stockCodes` — 한투가 붙인 종목코드(네이버 줄은 `[]`)
    - `url` — 원문 링크(없으면 null — 한투만 있는 줄)
    - `description` — 네이버 스니펫(없으면 null)
    - `receivedAt` — gh-radar 가 받은 시각

**시각은 전부 `+09:00` 오프셋 ISO** — `YYYY-MM-DDTHH:MM:SS.sss+09:00`(서버 TZ 무관).

**응답 예시**(`GET /api/news/by-stock?codes=012340,005930` — 기본 파라미터 · 공시 1 · 네이버 1 · 빈 코드 1):

```json

  "feedAt": "2026-11-12T09:15:00.512+09:00",
  "stocks": [
    {
      "code": "012340",
      "collectedAt": "2026-11-12T09:14:10.000+09:00",
      "count": 2,
      "truncated": false,
      "items": [
        {
          "id": "naver:11111111-1111-4111-8111-111111111111",
          "kind": "news",
          "publishedAt": "2026-11-12T09:20:00.000+09:00",
          "title": "가람전자, 대형 공급계약 수주에 강세",
          "source": "한국경제",
          "stockCodes": [],
          "url": "https://example.invalid/n1",
          "description": "가람전자가 장 초반 강세다.",
          "receivedAt": "2026-11-12T09:25:00.000+09:00"
        },
        {
          "id": "kis:2026111209143512345",
          "kind": "disclosure",
          "publishedAt": "2026-11-12T09:14:35.000+09:00",
          "title": "(주)가람전자 단일판매ㆍ공급계약체결",
          "source": "코스닥 공시",
          "stockCodes": ["012340"],
          "url": null,
          "description": null,
          "receivedAt": "2026-11-12T09:14:41.230+09:00"

    { "code": "005930", "collectedAt": null, "count": 0, "truncated": false, "items": [] }

```

### 뜻 — gh-trade 가 가를 것

- **`collectedAt: null`** = 그 종목을 아직 종목별로 모으기 전이다. 전체 흐름으로 들어온 글은 이미 `items` 에 있을 수 있다. 「수집 전」 표시는 이 값으로 가른다.
- **`collectedAt` 이 있고 `items: []`** = 모았는데 최근 기간에 글이 없다.
- **`feedAt`** = 수집기 전체 흐름의 마지막 성공. 평일 `07:00` ~ `20:00` 에 1분 넘게 안 바뀌면 수집기가 멈춘 것이다(그 밖 시간대는 10 ~ 30분 간격이라 정상).
- **`count`** = 읽기 상한(출처별 `limit`+10건 · 최대 110) 안에서 한투 · 네이버를 합친 뒤 건수. 어느 출처든 그 상한에 닿으면 `truncated: true` — 배지는 「N건+」 로 그린다. `days=3&limit=3` 이면 출처별 13건까지 읽는다.
- **등록:** 이 조회가 그 종목을 수집 대상으로 등록한다. 한투 호출은 gh-radar 서버가 차례로 한다(클라 · 사용자 수와 무관). 10분 동안 조회가 없으면 대상에서 빠진다.
- **첫 수집까지 약 10 ~ 15초** — 수집 대상 다시 읽기 10초 + 새 등록 종목 우선. 이후 종목별 보충 조회는 한 바퀴 1 ~ 3분. 공시는 전체 흐름으로 5초 안팎에 들어온다(종목 등록과 무관).

### 거르기 · 합치기 — gh-radar 가 한 번만 한다(클라는 받은 대로 그린다)

- **공시:** 파생상품 안내만 뺀다 — ELW · ETN · ETF 종목에 붙은 글, 제목이 ELW · ETN · ETF · 주식선물 · 주식옵션 안내인 공시. 투자주의 · 경고 · 단기과열 · 거래정지 같은 **시장 조치와 회사 공시는 전부 표시**한다. 수집 하루 뒤 사용자 확인으로 거르기 규칙을 다듬을 수 있다 — 바뀌어도 계약 모양은 그대로다.
- **한투 뉴스:** 한투가 붙인 종목 그대로 전부 보인다(테마 기사 · 가끔 엉뚱한 기사 포함 — 사용자 결정). 제목 종목명 필터는 없다.
- **같은 기사 합치기:** 한투 · 네이버 둘 다 있으면 한 줄 — 시각은 이른 쪽, 링크 · 스니펫은 네이버 것. 네이버가 3 ~ 9분 늦게 오면 그때 `url` 이 붙는다(같은 `id` 그대로).
- **수정본:** 같은 날 다른 일련번호로 다시 온 수정본은 한 줄로 남는다. 「(정정)」 공시는 원 공시와 별개 줄이다(제목 앞 「(정정)」 그대로).
- **`id` 는 한 번 정해지면 바뀌지 않는다 — 새 글 강조는 id 로** 한다(이전 응답에 없던 `id` = 새 글).
- 목업의 「삭제 공시는 줄을 지웁니다」는 이 계약에 없다 — 삭제 신호 필드를 주지 않는다.

## gh-trade 가 할 일

- **화면(사용자 결정 D-21):**
  - 돌파감지 = 행에 배지 + 창 아래 상세 패널(목업 **돌파 C**)
  - 상따창 = 종목 줄 아래 한 줄 띠(**상따 1**)
  - **알림음 없음**
  - 매집감지 창 · 종합매매창에는 넣지 않는다
  - 표시만 한다 — 판정 · 주문에는 쓰지 않는다
  - 뉴스 줄에는 언론사 이름(`source`)과 원문 링크(`url` 이 있을 때)를 같이 보인다
- **호출:** `days=3&limit=3`(사용자 결정). 파라미터를 빼면 gh-radar 기본 `days=3&limit=20` 이다.
  - 배지 · 띠는 `days=3&limit=3` 응답 하나로 그린다.
  - 상세 패널용으로 선택한 종목만 큰 `limit`(예: `codes=<선택 종목>&days=3&limit=20`)으로 따로 부른다.
- **조회 권장:** 10초 주기 · 한 번에 100코드 묶음 · gzip(`Accept-Encoding: gzip`).
  - 서버 5초 캐시 · 전용 제한 IP 당 분 600회(사무실 여러 대가 같은 공인 IP 인 것을 감안한 숫자 · 테마 · 시세 조회의 분 200회와 따로 센다).
  - 실패(404 · 429 · 5xx · 시간 초과)면 마지막 데이터를 그대로 두고 다음 주기에만 다시 부른다 — 즉시 재시도 금지.
- 이번 요청에 `.fbs` · 실거래 서버 변경은 없다 — 클라(돌파감지 창 · 상따창)만.

## 배포 순서 제약

gh-radar 먼저 배포가 안전한가: **예 — gh-radar 먼저.** 이 경로는 gh-radar 41-09 배포 뒤에 생긴다(그 전엔 404). gh-trade 클라가 404 를 「아직 없음」 으로 조용히 넘기도록 만들면 클라를 먼저 배포해도 된다. `.fbs` · 실거래 서버 변경이 없어 서버 배포(cloud-verify · deploy.sh)는 필요 없다.

gh-trade 는 cloud-verify.sh 게이트 뒤 deploy.sh <broker> <env> 로 KB 120·121·교보 119 를 장 마감 뒤 배포한다.

## 확인 방법

1. 응답 모양: `curl -s --compressed '<server>/api/news/by-stock?codes=005930,000660&days=3&limit=3'` — `asOf` · `feedAt` · `stocks` 두 줄(입력 순서) · 시각 `+09:00`.
2. 캐시: 같은 요청을 5초 안에 두 번 → `asOf` 가 같다.
3. 등록 · 첫 수집: 수집 대상 밖 코드 하나를 넣어 부르고 15초 뒤 다시 → 그 코드의 `collectedAt` 이 null 에서 시각으로 바뀐다.
4. 화면: 돌파감지 행 배지 · 상세 패널, 상따창 한 줄 띠에 제목이 보이고, 새 `id` 줄이 강조된다.
