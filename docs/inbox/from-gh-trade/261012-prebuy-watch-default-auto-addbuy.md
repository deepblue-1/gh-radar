# gh-trade → gh-radar 인계 — 2026-10-12

## 바뀐 것

와이어 무변경(.fbs·84/42 사용자 설정·relay 모두 그대로). WinForms 「기본설정 - 상따전략」 창의 선매수 줄에 옵션 2개를 넣었다(quick-261012-sd1, 트렐로 「매매설정창 추가」). 사용자가 「gh-radar 도 매매설정 페이지가 있으니 같은 내용을 넣어 달라」고 해서 웹 반영을 요청하는 노트다.

1. **선매수 「매도잔량」 기본값 (단위 만원)** — 0 이면 상따창을 열 때 지금과 같다(빈칸 → 상장주식수 × 0.3% 를 상한가로 환산해 만원으로 채움). 0 이 아니면 상따창 선매수 매도잔량 칸(WinForms `numBuyWatchQty`)을 그 값 그대로 채우고, 상장주식수 시딩은 이 칸만 건너뛴다(체결량·줄매수 최소/최대·매도 체결 시딩은 그대로). 서버에 그 종목 전략이 있으면 지금처럼 서버 에코 값이 이긴다. 범위 0~999,999,999.
2. **「☐줄매수 자동켜짐」 체크박스** — 켜 두면 상따창에서 사람이 ☐선매수를 켤 때 ☐줄매수가 꺼져 있으면 **같은 제출(한 번의 등록)** 에 ☐줄매수도 켠다. 결과는 두 체크를 손으로 다 켠 것과 같다(줄매수를 켤 때 따라 켜지는 ☐버스트 취소 자동 체크도 적용). 제출이 실패하면 ☐줄매수도 함께 되돌리고, 성공하면 상태 로그 「선매수 체크 — 줄매수도 켬」 한 줄. ☐선매수를 끌 때는 ☐줄매수를 건드리지 않는다. 서버 에코로 선매수가 켜지는 경우에는 동작하지 않는다(사람 토글만). 상따창 줄매수 줄의 기존 「☐자동」(add_buy_auto — 서버가 이탈 뒤 줄매수를 다시 켜는 설정)과는 **다른 기능**이라 라벨을 「자동켜짐」으로 구분했다.

**저장 위치:** WinForms 는 두 값을 그 PC 의 settings.ini `[LimitChaserDefaults]`(`PreBuyWatchAmount`·`PreBuyAutoAddBuy`)에만 둔다 — 서버 사용자 설정(84/42)에는 싣지 않았다. 그래서 웹과 WinForms 가 값을 공유하지 않는다.

## gh-radar 가 할 일

relay·DB·스키마 재동기화 필요 없음. 웹만:

- `webapp/src/components/me/limit-chaser-defaults.tsx`(매매설정 페이지) 선매수 줄 아래에 「매도잔량 [ ]만」 칸과 「☐줄매수 자동켜짐」 체크를 추가.
- 웹 상따 등록 폼(`limit-chaser-form` 계열) — 기본값 채울 때 매도잔량 > 0 이면 그 값, ☐선매수를 사람이 켤 때 설정이 켜져 있으면 ☐줄매수도 같은 제출에 켜기(실패 시 함께 되돌림). 위 「바뀐 것」 의 규칙과 같게.
- 저장소: 서버 필드가 없으므로 웹 쪽 저장(브라우저 등)으로 한다. 기기 간 공유가 꼭 필요하면 아래 「질문」 대로 역방향 인박스로 요청해 달라.

## 배포 순서 제약

gh-trade 서버 먼저 배포가 안전한가: 해당 없음 — 서버 무변경(WinForms 클라 발행만).

gh-radar 쪽 순서는 항상 DB → relay → webapp 이고, push 가 곧 webapp 프로덕션 배포다.

## 확인 방법

- 매매설정 페이지에서 매도잔량 50 저장 → 서버에 전략이 없는 종목의 상따 폼을 열면 선매수 매도잔량 칸이 50(만원). 0 으로 저장하면 종전처럼 상장주식수 시딩 값.
- 「줄매수 자동켜짐」 켜고 ☐선매수 클릭 → ☐줄매수·☐매수주문(마스터)이 함께 켜진 한 건의 등록이 나가고 서버 에코에서 pre_buy_enabled·add_buy_enabled 둘 다 true.
