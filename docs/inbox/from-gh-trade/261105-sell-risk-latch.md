# gh-trade → gh-radar 인계 — 2026-11-05

## 바뀐 것

**와이어·fbs·에코 필드 무변경** — MsgType·필드·슬롯·vtable 그대로, 생성물 재동기화 불필요. 상따 ☐위험도(`sell_risk_enabled`·`sell_risk_pct`, SetLimitChaserReq(10) vtable 180·182)의 **의미만** 세 가지 바뀐다(gh-trade 커밋 aa331275, quick-261105-fgg).

1. **3초 위험도 래치 뒤에만 발동** — 서버가 「상한가 매수잔량 > 0 ∧ 위험도 < N」 이 3초 이어진 뒤에만 래치를 켜고, 래치가 켜진 뒤에만 위험도 ≥ N 이 발동한다(상한가 진입 직후 벽 출렁임 오발동 방지). 벽 0(매수1호가가 상한가 밖)이면 래치 리셋. 래치 상태는 와이어·에코에 싣지 않는다.
2. **상한가 미만 체결은 ☐위험도를 끄지 않는다** — 종전에는 상한가 깨짐이 `sell_risk_enabled` 를 OFF 로 내렸지만, 이제 ☐위험도는 켜 둔 채 래치만 리셋한다(다시 잠기면 3초 뒤 재래치·재발동). 에코 `sell_risk_enabled` 가 OFF 로 내려가는 사유 목록에서 「상한가 깨짐」 이 빠졌다(남은 것: 발동·매도 송신·매도 OFF·일괄매도·재기동·후매수 재진입 매도 꺼짐).
3. **C# 클라 선·줄매수 자동 체크가 ☐위험도도 켠다** — 사람이 선매수·줄매수를 켤 때 ☐매도주문이 켜져 있거나 같이 켜지면 ☐위험도도 같은 제출(변경 마스크 비트 52)로 켠다. 서버 쪽에서 보면 여전히 사람 제출로 켜진다.

## gh-radar 가 할 일

- 생성물 재동기화·relay 파서·DB 마이그레이션: **불필요**(와이어 무변경).
- 웹 lc.set 재제출(`buy3_schema` ≤ 7)은 종전대로 서버 값 유지 — 래치와 무관, 변경 없음.
- 웹 화면·도움말에 「켜는 것은 사람뿐」·「상한가 깨짐 시 ☐위험도 꺼짐」 같은 문구가 있으면 갱신 대상(→ 「3초 래치 뒤 발동 · 상한가 깨짐은 래치만 리셋」).
- 웹도 매수 그룹(선·줄매수)을 켤 때 ☐위험도를 함께 켤지는 gh-radar 판단(C# 클라는 이번에 켜도록 바꿨다).

## 배포 순서 제약

gh-trade 서버 먼저 배포가 안전한가: 예 — 와이어 무변경이라 순서 제약 없음.

gh-radar 쪽 순서는 항상 DB → relay → webapp 이고, push 가 곧 webapp 프로덕션 배포다.

## 확인 방법

- 서버 로그 `[LimitChaser] 위험도 래치 켜짐 isin= 위험도= 기준= 벽= 합산= 유지=ms 거래소=` · `[LimitChaser] 위험도 래치 리셋 — {벽 없음|상한가 깨짐} ...` 이 전이 때 1줄씩 나온다.
- 상한가 미만 체결 뒤에도 웹 상따 행의 ☐위험도 에코가 ON 으로 남는다.
